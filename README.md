# AI 短剧全流水线

这个仓库是一套"从选题到成片"的 AI 短剧制作流水线，配合 **Claude Code** 使用。
每一个环节都封装成一个 Claude Code skill（`.claude/skills/` 下），按顺序执行
即可把一个故事创意变成：故事大纲 → 分镜表 → 人物/场景立绘 → 关键帧图 → 图生
视频提示词 → 可提交给 LTX-2.5 的生成任务 → 实际跑出来的视频片段。此外还有一个
本地/局域网小网站，给不懂技术的剧本家看产出、提意见。

> 给 Claude 用的更详细索引见 [`INDEX.md`](./INDEX.md)（文件/目录级别的定位表）。
> 这份 README 是给**人**看的使用说明。
>
> 不知道东西放哪了、想知道现在做到第几集，直接对 Claude 说 **`/index`**（或"这个
> 文件在哪""现在做到哪一步了"），它会读索引 + 现扫磁盘给你实时进度，不用自己翻目录。

## 这套流水线是怎么被使用的

你不需要自己写代码或调 API。所有步骤都是在 **Claude Code 对话里用中文说一句
话**触发对应 skill，Claude 会自己读取上一步产出的文件、调用脚本、把结果存到
`output/<剧名>/` 下。你只需要按顺序把关键词说给 Claude 听（下面每一步都列了
触发词），并在每一步验收产出（同意/打回重做）。

## 开始之前：环境准备

1. **Codex CLI 登录（出图必需）**：人物立绘、场景图、关键帧图默认走 Codex CLI
   （用 ChatGPT 账号登录，不需要额外 API key/计费），需要在本机执行一次：
   ```bash
   codex --version          # 没装先 npm install -g @openai/codex
   codex login --device-auth
   ```
   按提示在浏览器里用 ChatGPT 账号（需要 Plus/Pro/Team 等订阅）完成登录，
   凭证会缓存在 `~/.codex/`，之后长期有效，不用每次都登。
2. **LTX-2.5 实际生成（可选，到最后一步才需要）**：需要 vast.ai 等 GPU 租赁
   平台的账号和 API key，会真实产生费用，用到再准备。

## 流水线七步

每一步都承接上一步的产出物作为输入，顺序不能跳（除非你已经有现成的中间产物）。

### 1. 选题 / 大纲 —— `short-drama-scout`

**做什么**：由 Claude 原创设计一个适合 TikTok 发布的短剧故事——可以完全自主
选题，也可以按你给的方向/关键词深化，或者拿你给的结构化选题大纲（题材/卖点/
目标观众/集数）去补全。

**产出**：故事梗概、人物小传、12-15 集分集大纲（每集含开场钩子、核心冲突、
结尾悬念）、TikTok 发布建议。

**怎么触发**：跟 Claude 说"设计短剧故事" / "帮我编个短剧" / "按这个方向写
短剧" / "这个题材适合拍短剧吗"。

### 2. 分镜设计 —— `short-drama-storyboard`

**做什么**：把故事/大纲拆成可以直接拿去出图/出视频的分镜表——先定视觉风格
（写实/动漫/半写实）和叙事节奏，再逐集逐镜设计画面、人物动作、景别、运镜、
转场、时长，并标注每个镜头该用"静态运镜/图生视频/精细抠图"哪种档次（省钱又
不牺牲效果）。同时产出可以直接喂给图像模型的人物形象提示词、场景提示词。

**产出**：`output/<剧名>/storyboard/` 下的 `style_bible.md`（画风圣经）、
`characters.md`（人物提示词档案）、`scenes.md`（场景提示词档案）、
`ep01.md ~ ep0N.md`（逐集分镜表）。

**怎么触发**："做分镜" / "设计故事板" / "定短剧画风" / "生成人物形象提示词"。

### 3. 出图（人物立绘 + 场景图）—— `short-drama-image-gen`

**做什么**：读取上一步的人物/场景提示词，调用 Codex CLI 批量出图。人物固定
出"三视图"（正面+侧面+背面合一张，一次出多版供挑）；场景按需要的时段/版本
多出几组。Claude 会逐张实际查看，对照人设/画风一致性/竖屏构图验收，不合格就
调整提示词重生成，直到选出可用的图。角色图和场景图互不依赖时可以并行生成。

**产出**：`output/<剧名>/assets/` 下按人物/场景分的图片目录，加
`jobs_*.json`（出图任务清单）、`manifest.append.jsonl`（生成日志）、
`selected.md`（已选中的图）。

**怎么触发**："生成人物立绘" / "生成角色三视图" / "生成场景图" / "出图" /
"角色和场景同时出图"。

### 4. 关键帧生成 —— `short-drama-keyframe-gen`

**做什么**：不是每一镜都出图，而是从每集分镜表里挑出约 8-12 个真正关键的
镜头（开场钩子、结尾钩子、高光镜、核心冲突反应镜），把简写提示词展开成完整
prompt，引用对应的人物+场景基准图，合成出这一镜的关键帧图。逐张核对是否还原
了画面/景别/一致性，不合格就调整重生成。

**产出**：`output/<剧名>/keyframes/ep0X/` 下按镜头分的图片目录
（`ep0X_镜NN/`）、`jobs_ep0X*.json`、`keyframes.md`（索引说明）。

**怎么触发**："生成关键分镜图" / "按分镜出关键帧" / "把这集分镜做成图" /
"这一集挑几个镜头出图"。

### 5. 图生视频提示词 —— `short-drama-video-gen`

**做什么**：把关键帧和分镜表里的"运动描述"结合，为 S/A 级镜头把动作拆解成
"起始姿态 → 过程关键点 → 结束姿态"，展开成可直接提交给可灵/即梦/Vidu/
PixVerse/海螺/Runway/Veo 等图生视频平台的完整提示词（含运镜、光影变化、结尾
定格、负面提示词），并给出防止人脸崩坏/动作失控的稳定性方案。B 级镜头不进
图生视频模型，改用本地零成本的 ffmpeg 推拉摇移脚本直接出视频。

> 这一步没有免 API key 的自动化通道（出图能用 Codex CLI 免费跑，视频生成
> 平台目前都要人工网页提交或者自建通道），产出主要是**提示词和任务清单**，
> 不是一键出片。

**产出**：`output/<剧名>/videos/ep0X/` 下的 `video_jobs.md`（提示词清单）等。

**怎么触发**："把关键帧做成视频" / "生成图生视频提示词" / "这一镜怎么做
动画" / "关键帧转视频"。

### 6. 打包给 LTX-2.5 —— `short-drama-ltx-export`

**做什么**：如果你自建了 LTX-2.5（Lightricks LTX-2）图生视频通道，这一步把
上一步"给人看的" `video_jobs.md` 转成严格结构化、补齐 LTX 专属字段
（`width`/`height`/`num_frames`/`seed`）的 `video_jobs.json`，同时检查/生成
`ltx_remote_config.json`，最后跑一次 dry-run 校验能否被脚本直接消费。

**产出**：`output/<剧名>/videos/ep0X/video_jobs.json`、`ltx_remote_config.json`。

**怎么触发**："把这些整理成能交给LTX的文件" / "导出video_jobs.json" /
"打包提交给LTX2.5"。

### 7. 实际生成（真花钱）—— `short-drama-ltx-generate`

**做什么**：拿校验好的 job 文件，去 vast.ai 等平台用你提供的 API key 租显卡
（或复用已有实例）、SSH 部署 LTX-2 环境、下载模型权重、真正提交生成任务、
监控进度、下载结果、抽帧+听审验收。

**产出**：`output/<剧名>/videos/ep0X/` 下的 `ep0X_镜NN.mp4`、
`ep0X_full_preview.mp4`（拼接预览）、`ltx_submit_results.json`。

**怎么触发**："帮我实际生成视频" / "调用显卡跑" / "执行生成任务" /
"这一步真的把视频跑出来"。**注意：这一步会真实产生 GPU 租赁费用。**

## 每部短剧的产出物在哪

所有产出按剧名分目录存放：

```
output/<剧名>/
  storyboard/    画风圣经 + 人物/场景提示词档案 + 逐集分镜表（第 1-2 步）
  assets/        人物三视图/表情差分、场景图（第 3 步）
  keyframes/     每集关键帧图（第 4 步）
  videos/        图生视频提示词、LTX 任务文件、成片（第 5-7 步）
  _web_state/    剧本家在协作网站上的评论/入选标记/编辑记录（review.json，要提交）
```

目前仓库里有三部示例/进行中的项目：`出狱后我成为了非洲矿王`（进度最完整）、
`千金归位`、`暗局`。

## 给剧本家用的协作网站

流水线跑出来的东西不方便让不懂技术的剧本家直接看文件，所以 `web/` 下有一个
零依赖的本地/局域网小网站：给剧本家看分镜表、立绘、关键帧、视频，留言、直接
改分镜文字、对图片一键重新生成。

**启动**（纯 Python 标准库，不需要 `pip install`/`npm install`）：

```bash
python3 web/server/app.py --port 8000
```

浏览器打开 `http://localhost:8000` 自己用；同一局域网内的剧本家把 `localhost`
换成这台机器的局域网 IP（比如 `http://192.168.1.23:8000`）就能访问，不需要装
任何东西。**必须在这台机器上启动**——图片"重新生成"按钮依赖本机已登录的
Codex CLI，服务进程会直接在本机起 `codex exec` 子进程出图。

剧本家的所有反馈（评论、图片入选标记、分镜表文字修改的审计记录、重新生成
请求）都落在对应项目的 `output/<剧名>/_web_state/review.json` 里，下次处理
这个项目时直接读这份文件就能看到剧本家提了什么意见。

更详细的设计说明、"重新生成"按钮的能力边界、已知限制见 [`web/README.md`](./web/README.md)。

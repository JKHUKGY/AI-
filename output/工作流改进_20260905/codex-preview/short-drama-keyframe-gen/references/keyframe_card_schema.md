# 关键帧卡 keyframe_cards.json 结构定义

关键帧卡是**分镜表和出图提示词之间的中间层**，和 `short-drama-video-gen` 的
`shot_cards.json` 是同一套思路：**提示词不手写**，人只维护卡上的字段，
提示词由 `scripts/build_keyframe_prompt.py` 按固定模板机械装配——同一张卡
永远装配出同一段字符串。要改提示词，只能改卡上的字段再重跑脚本。

落盘位置：`output/<故事名>/keyframes/ep0X/keyframe_cards.json`。

**顶层有两种格式**（2026-09-04 起新项目一律用新版）：

```jsonc
// 旧版：顶层直接是卡的数组。照旧能跑，但连戏那几条校验只能报 WARN
[ {卡}, {卡}, ... ]

// 新版：多一层「场次节拍」
{
  "scene_beats": [ {节拍} ],   // 这一场此刻谁在场、房间什么状态、主帧是哪张
  "cards":       [ {卡} ]      // 一张卡 = 分镜表里的一镜
}
```

**一张卡 = 分镜表里的一镜。** 一集 27 镜就是 27 张卡。

它存在的理由是这一步真实失败过的三种方式（证据见 `blocking_guide.md`）：

1. 朝向靠散文暗示 → 模型默认给正脸，多人镜变成"全员面对镜头的合影"。
2. 纵深不写 → 几个人并排站在同一条线上，像列队。
3. 景别写成一句尾巴 `【景别】中景`，同时又要求"保持场景与底板完全一致" →
   两条指令打架，画面退回底板那个大全景。

这三样在卡上都是**必填的枚举或必填的裁切说明**，脚本会硬拦。

**2026-09-04 又加了第四种和第五种**（《出狱后》v2 ep01 实拍出来的）：

4. **在场的人没有交代 → 画面里的家具是空的。** ep01 场次 1-3 九镜，
   四个人全程在客厅，其中五镜的画面里明明有那张沙发，卡上却一个字没写
   沙发上坐着的两个人——出来的图沙发是空的（`ep01_镜25`）。
   卡上原来只有 `people[]`，语义是"这一镜要演的人"；**"画面里应该看得见谁"
   是另一件事，以前没有字段承载它**。现在有 `background_people[]` 和
   `present_off_frame[]`，加上 `scene_beats[].present` 做判据。
5. **近景/特写挂在宽景底板上 → 模型重新合成一个相机。** 底板里没有那个
   距离的像素，"推近 2.1 倍"只能靠现编；一旦它重新合成相机，
   "保持场景与参考图一致"就整体失效，房间里还有谁、背后是什么全部重来。
   `ep01_镜24` 标着 `A主机位`、出来是一个全新机位就是这么来的。
   现在底板分**宽/紧两档焦段**，景别和焦段对不上直接 ERROR。

## `scene_beats[]`：场次节拍（新版格式的第一层）

**一个节拍 = 一场戏里"房间状态没变"的一段。** 场景换了要换节拍；
房间状态发生了不可逆的变化（有人离开、门关上、东西被放下）也要换节拍。
ep01 一集 35 镜拆成 7 个节拍。

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | `ep{集号}_b{序号}`，如 `ep01_b3`。卡用 `beat_id` 挂上来 |
| `scene` | ✅ | 场景编号，和卡的 `scene` 必须一致 |
| `title_zh` | 建议 | 一句话说这一节拍是什么，只给人看 |
| `present` | ✅ | **这一节拍在这个房间里的所有人**（不是"这一镜出场的人"）。这是连戏校验的唯一判据。空镜节拍填 `[]` |
| `seating` | 建议 | `{人名: 家具名}`，谁此刻在哪件家具上。用来核对"画面里有那张沙发，沙发上的人却被声明在画外" |
| `state_zh[]` | ✅ | 这个房间此刻的既成事实：跨镜复用的道具长什么样、谁坐着没起来、门开着还是关着。**每一镜都会重复一遍**——模型不跨镜记忆 |
| `light_zh` | 建议 | 这一节拍的光。卡上没写 `light_zh` 时用它兜底，保证同一场戏光线一字不改地复用 |
| `master_plate_id` / `master_plate_image` / `master_plate_read_zh` | 出主帧时✅ | 主帧从哪个机位底板派生。规则同卡上的 `plate_*` |
| `blocking[]` | 出主帧时✅ | 主帧里**每一个在场的人**的走位。字段同 `people[]`，另有 `holding_zh`（手里拿着什么）。`present` 里的人一个都不能漏 |
| `style_anchor_zh` / `camera_zh` / `avoid_extra_zh` / `count` | | 同卡上的同名字段 |
| `master_frame` | 出图后回填 | 主帧选中图的路径。**填了之后这一场的中景/全景镜会自动改用它当参考图1** |

主帧的提示词由 `scripts/build_master_frame_prompt.py` 装配，同样不手写。

### 主帧为什么不违反「never let one shot seed the next」

`研究.md` §2.7 引的那条纪律禁的是**链式**：A 生 B、B 生 C，漂移会累积。
主帧是**星形**——一场戏所有镜头都回到同一张主帧，和"所有镜头都回到同一份
三视图"是完全相同的拓扑。三视图锁"这个人长什么样"，主帧锁"此刻这个房间
是什么样、谁站在哪、手里拿着什么"。

### 主帧顶替不了紧底板

主帧也是一张宽图。从主帧里裁特写和从底板里裁特写是**同一个像素问题**。
所以：近景/特写走紧底板，中景/全景走主帧。装配器就是按这个规则选参考图1 的。

|---|---|---|---|
| `id` | ✅ | ✗ | `ep{集号:02d}_镜{镜号:02d}`，如 `ep03_镜03`。作为输出子目录名 |
| `shot_no` | ✅ | ✗ | 分镜表镜号（整数） |
| `scene` | ✅ | ✗ | 场景编号，抄分镜表「场景编号」列 |
| `beat_id` | 新版✅ | ✗ | 挂到哪个 `scene_beats[]`。有 scene_beats 却不填直接 ERROR |
| `tier` | 建议 | ✗ | `S`/`A`/`B`/`C`，抄分镜表「分级」列 |
| `plate_id` | ✅ | ✗ | 机位底板 id，如 `SC03_顾家别墅客厅_B反打`。抄分镜表「机位」列。**近景/特写要挂带 `_紧` 后缀的紧底板**，见下 |
| `plate_image` | ✅ | ✗ | 该底板选中图的路径。查 `selected.md`，查不到就**报缺**，不要顶替 |
| `plate_read_zh` | ✅ | ✗ | **看过底板图之后**如实写这张底板里左/中/右/纵深各是什么、地面占多少。见下 |
| `script_ref_zh` | ✅ | ✗ | 抄分镜表「剧本原文锚点」列。给人和 Reviewer 验收用，**不进提示词** |
| `beat_zh` | ✅ | ✗ | 抄分镜表「画面描述」列原文。只是给人在审阅表里对照，**不进提示词** |
| `style_anchor_zh` | ✅ | ✅ | 画风锚点，从 `style_bible.md`/`characters.md` 开头**原句抄**，全集一致 |
| `camera_zh` | ✅ | ✅ | 相机站在房间哪个位置往哪看 + 机高。从 `scenes.md`「空间关系」块翻过来 |
| `framing.shot_size` | ✅ | ✅ | 景别，抄分镜表「景别」列（`特写`/`近景`/`中近景`/`中景`/`全景`…） |
| `framing.subject_frac` | ✅ | ✅ | 主体在画幅**高度**上占的比例（0–1）。脚本按景别查区间 |
| `framing.crop_zh` | ✅ | ✅ | 画面上下边**切在人身上哪里**、地面/天花各留多少。见下 |
| `framing.plate_crop_zh` | 非全景时✅ | ✅ | 这一镜取底板的哪一块、放大多少、底板里哪些东西这一镜看不到了。见下 |
| `light_zh` | 建议 | ✅ | 光从哪来、打在谁身上。抄分镜表画面描述里的光线句 |
| `people[]` | ✅（**纯道具镜**才填 `[]`） | ✅ | 逐人走位，见下方专门一节。**只露手/背影等局部、但这个局部属于已建立角色时，仍然要把他放进 `people[]` 并给参考图**，见下 |
| `background_people[]` | 有人在画面里但不是主体时✅ | ✅ | **在画面里、但不是这一镜表演主体的人**。字段和 `people[]` 同构，见下方专门一节 |
| `present_off_frame[]` | 同上 | ✗ | 这一节拍在场、但这一镜**确实在画外**的人名数组。这是一次**表态**，不是可以省略的字段 |
| `plate_tier_waiver_zh` | ✗ | ✗ | 近景/特写确实要用宽底板顶一次时，写清为什么。写了才把 ERROR 降级成 WARN |
| `props_zh` | ✗ | ✅ | 道具及其位置的中文短句数组。`people` 为空的道具镜必填。**不要拿它写人**——人走 `background_people[]` |
| `relation_zh` | 多人时建议 | ✅ | 一句话讲这一镜的人物关系落差（"她凑近问、他懒得答"） |
| `avoid_extra_zh` | ✗ | ✅ | 追加进"避免"尾块的本镜专属条目。**不许写朝向/景别**，见下 |
| `count` | ✗ | ✗ | 本次派发实际生成张数，**默认1**；按运行模式和用户决定填写，不等同每轮预算。新任务各轮最多1／2／3张，达标早停，见generation_modes.md |
| `notes` | ✗ | ✗ | 自由备注，原样带进 `jobs.json` 的同名字段 |

## `people[]`：逐人走位（这一层是本 skill 的核心）

```json
{
  "name": "顾万通",
  "ref_images": ["output/.../顾万通_得势期_背面转身_00.png"],
  "ref_note_zh": "背面转身基准图",
  "pos_x": "right",
  "depth": "near",
  "body_dir": "screen_left",
  "camera_relation": "three_quarter_back",
  "gaze_at": "off_down",
  "posture_zh": "刚甩完包站定，重心压在右腿，胸口一起一伏",
  "action_zh": "左手把已经松开的领带整条攥进手心，脸只略微转向刘兰的方向",
  "contact_zh": null
}
```

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `name` | ✅ | | 角色名，和 `characters.md` 一致 |
| `ref_images` | ✅ | | 该角色基准图路径数组（1–2 张）。查不到对应造型/视图就**报缺** |
| `ref_note_zh` | 建议 | | 这几张参考图是什么视图，会写进"参考图N 是…"那句 |
| `pos_x` | ✅ | `far_left`/`left`/`center`/`right`/`far_right` | 在画幅横向的位置 |
| `depth` | ✅ | `near`/`mid`/`far` | 纵深层。**多人镜必须至少有两个不同的层** |
| `body_dir` | ✅ | `screen_left`/`screen_right`/`to_camera`/`away` | 身体朝画面哪边/朝镜头/朝纵深里 |
| `camera_relation` | ✅ | `front`/`three_quarter_front`/`profile`/`three_quarter_back`/`back` | **相对镜头**露多少脸。词表和规则见 `blocking_guide.md` |
| `gaze_at` | ✅ | 另一个人物名 / `lens` / `off_left` / `off_right` / `off_up` / `off_down` / `prop:<名>` | 视线落点 |
| `posture_zh` | ✅ | | 身体姿态、重心、坐/站/蹲/半躺 |
| `action_zh` | ✅ | | 这一**瞬间**在做什么（手在哪、脸上什么表情）。写瞬间，不写过程 |
| `contact_zh` | ✗ | | 和别人/家具的接触点（"右手撑在沙发扶手上"）。没有就 `null` |

### `body_dir` 和 `camera_relation` 必须自洽

脚本硬拦不自洽的组合：

- `body_dir: to_camera` → `camera_relation` 只能是 `front` / `three_quarter_front`
- `body_dir: away` → 只能是 `back` / `three_quarter_back`
- `body_dir: screen_left` / `screen_right` → 只能是 `profile` /
  `three_quarter_front` / `three_quarter_back`

### `gaze_at` 指向另一个人时，朝向要跟着对

如果视线目标在自己的画面右边，`body_dir` 就必须是 `screen_right`
（`to_camera`/`away` 只给 WARN，因为偶尔"看着他却不转身"是刻意的）；
目标在左边同理。两人 `pos_x` 相同时脚本没法核对，会报 WARN 让人自己看。

## 道具连戏：`state_zh` 声明了还不够，**当事人的 `action_zh` 里也要拿着**

`scene_beats[].state_zh` 会被这一场每一镜的提示词自动重复一遍，这解决了
"跨镜道具变样"。但它**解决不了"道具凭空消失"**——2026-09-05 实测：

| 实拍 | 卡上写了什么 | 出来什么 |
|---|---|---|
| `ep01_镜04` | `b1.state_zh` 明写"江砚手里拎着一只半透明塑料袋"，但江砚的 `action_zh` 只写了脸和眼神、**没提手** | 他**空着两只手**（镜01/02/12/14/15 都拎着那只袋子） |
| `ep01_镜18` | `b2b.state_zh` 里**根本没声明那只登山包**（只声明了行李箱和纸片），两张卡的 `props_zh` 都只写"深色登山包" | 镜17/19 出成**深棕帆布包**、镜18 出成**深灰黑尼龙包**，同一段戏三镜换了只包 |

两条规则：

1. **凡是这一镜的人身上/手上有的东西，写进那个人的 `action_zh` 或 `contact_zh`。**
   模型是照着「这一瞬间他在做什么」画手的；`action_zh` 里手是空的，
   它就画空手，`state_zh` 里那句话拦不住。
2. **凡是跨镜复用的道具，`state_zh` 必须写死它的外观，而且要写到能排除歧义。**
   "深色登山包"不够——"深色"既可以是黑尼龙也可以是深棕帆布。
   要写成"深棕色帆布登山包：磨白的织带肩带、两个金属搭扣、正面一个翻盖大口袋
   ——**不是黑色或深灰的尼龙包**"这种程度。
   道具**第一次出现在哪个节拍，它就要出现在那个节拍的 `state_zh` 里**，
   而不是等到它变成戏眼的那一场才写。

## `background_people[]` / `present_off_frame[]`：连戏这一层

**规则一句话**：`scene_beats[].present` 里的每一个人，这一镜必须落在三栏之一。

| 栏 | 意思 |
|---|---|
| `people[]` | 在画面里，而且是这一镜要演的人 |
| `background_people[]` | 在画面里，但不是主体（虚焦的、背对的、坐在后面没抬头的） |
| `present_off_frame[]` | 这一镜确实看不见他 |

**空着就是 ERROR。** 不表态就是 `ep01_镜25` 那种"沙发在画面里、沙发上的
两个人凭空消失"。

```json
{
  "name": "顾瑶",
  "ref_images": ["output/.../顾瑶_三视图/顾瑶_三视图_00.png"],
  "ref_note_zh": "三视图",
  "pos_x": "right", "depth": "far",
  "body_dir": "screen_left", "camera_relation": "profile",
  "focus": "defocused",
  "gaze_at": "prop:手机",
  "appearance_zh": "22 岁上下的东亚年轻女性、浅栗色长发、白色针织吊带背心",
  "posture_zh": "半躺陷在同一张黑色转角沙发上、一条小腿架在扶手上",
  "contact_zh": "半躺在黑色皮质转角沙发上"
}
```

- `pos_x` / `depth` / `body_dir` / `camera_relation` **必填**，取值和词表与
  `people[]` 完全一样，同样查 `body_dir × camera_relation` 自洽。
- `focus`：`defocused`（默认）/ `sharp`。
- **`ref_images` 和 `appearance_zh` 至少要有一个。** 两个都没有就 ERROR——
  没有参考图、也没有外观描述的背景人物，模型会按场景语境重新发明：
  `ep01_镜27` 第一轮的"两个女性虚焦身影"就出成了一男一女。
- 背景人物**不参与**多人镜那三条构图规则（不算"合影"、不算纵深层数、
  不占 `front` 名额）——他们本来就该退在后面。

### 装配器会替你抓的两条

1. **家具占用矛盾**：某人写进 `present_off_frame`，而 `scene_beats.seating`
   记着他此刻在「沙发」上，这一镜的 `plate_crop_zh` 又明写着取了沙发那一块
   → ERROR。画面里有那件家具，家具上的人就不可能在画外。
2. **没有 scene_beats 的老文件**：退化成"夹心检查"（某人在镜 N 和镜 N+2
   的画面里、镜 N+1 只字未提），只报 WARN——正反打里人在画外是正常语法，
   没有 `present` 名单就没有判据。**这就是要迁移到新版格式的理由。**

## 焦段：宽底板 / 紧底板

底板 id 带 `_紧` 后缀的是**紧底板**——同一个地点、同一个相机位置、同一个
朝向、同一种光，但相机已经推到拍人物近景/特写的距离，画面被近处的陈设填满、
背景轻微失焦。

| 景别 | 该挂哪一档 |
|---|---|
| 大特写 / 特写 / 近景 | **紧底板** |
| 中近景 / 中景 / 全景 / 远景 / 定场 | 宽底板（或场次主帧） |

对不上直接 ERROR。理由见本文档开头第 5 条：宽景底板里没有那个距离的像素，
"推近 2.1 倍"只能靠模型现编一个相机，而**一旦它重新合成相机，
"保持场景与参考图一致"就整体失效了**。

紧底板怎么出：拿该机位的宽底板当 `ref_images`，prompt 里写明"同一个地点、
同一个相机位置、同一个朝向、同一时刻的同一种光，唯一区别是相机推到了近景距离"，
并逐项点名左右关系（越轴关系必须跟着宽底板走）。
词表和命名见 `short-drama-storyboard/references/scene_prompt_template.md`。

## `plate_read_zh`：必填，而且必须真的打开底板图看过

和 `shot_cards.json` 的 `first_frame_state_zh` 是同一条纪律。理由一样：
底板被"保持场景与参考图完全一致"这句**锁死**，所以人往哪站、能站多近、
画面能裁到哪，全部由底板已经拍成什么样决定，不由想象决定。

填法（真实例子，`SC03_顾家别墅客厅_C侧机位`）：

> 实际看图确认：竖屏，画面左侧是黑色转角沙发与深灰大理石电视墙，
> 右侧至纵深端是落地玻璃幕墙和窗外泳池，中央上方悬水晶流苏吊灯。
> **画面下半部约 40% 是空的米白抛光大理石地面**——人如果按底板原样比例
> 站在沙发区，就只能占到画幅一半高，这一镜要的中景必须靠裁掉下方地面实现。

最后那一句就是 `framing.plate_crop_zh` 的依据。没看过图的人写不出这句。

## `framing`：景别怎么写才不漂

三个字段互相咬合，缺一个就会漂回底板的大全景：

- `shot_size` 是**说法**（分镜语言），单独存在没有约束力。
- `subject_frac` 是**数**。主体（多人镜取最靠前那个人）从头顶到画面底边
  占画幅高度的比例。脚本按景别查区间：

  | 景别 | `subject_frac` 合理区间 |
  |---|---|
  | 特写 | 0.75 – 1.0 |
  | 近景 | 0.50 – 0.80 |
  | 中近景 | 0.45 – 0.70 |
  | 中景 | 0.30 – 0.60 |
  | 全景 / 远景 / 定场 | 0.10 – 0.45 |

- `crop_zh` 是**裁切线**，而且**句式有讲究**（2026-09-03 修订）：
  必须写成"**画面底边把人物从<部位>处切断，看不到<看不到的东西>**"——
  用**切断**这个动词，并且明确说出**看不到什么**。

  | 写法 | 结果 |
  |---|---|
  | ✗ 底边切**在**两人大腿中段 | 模型理解成"大腿以下也要留着"，倾向把整个人塞进画面 → **出成全身** |
  | ✓ 画面底边把两人**从大腿中段切断，看不到膝盖以下和脚** | 才真的裁 |

  **实测教训（2026-09-03 样片）**：`ep01_镜01`/`ep01_镜04`/`ep03_镜10` 三镜标的都是中景、
  `subject_frac` 0.46–0.58，用"切在…"的句式**全部出成了接近全身**。
  模型的默认倾向是把人完整放进画面，只有明说"看不到脚"它才会切。
- `plate_crop_zh` 是**和底板锁定句的和解**。非全景镜必填，明写这一镜取底板
  的哪一块、放大多少、底板里哪些东西因此看不到了（"取底板画面中段并向前
  推近，纵深端玄关只保留上半部，下方空地面全部裁掉"）。不写这句，
  "保持场景与参考图完全一致"就会被理解成"连取景范围也一致"。

## `avoid_extra_zh`：可以有，但不许拿它写走位

Codex CLI 的 `image_gen` 没有独立的 negative prompt 参数，"避免"只能写进
prompt 尾块——这一点沿用 `short-drama-image-gen/references/jobs_schema.md`。
装配器会自动补一条固定的通用尾块（多余肢体/手指数量/五官崩坏/水印文字/
与参考图不符/多余人物），`avoid_extra_zh` 只加本镜专属的。

按 OpenAI 官方口径，"避免"里的内容要分两种看：

- **保留型否定 —— 官方推荐，该写，而且每一镜都重复**：`no watermark`、
  "画面内文字字幕"、"多余人物"、"与参考图不符"。它保护的是**已经存在的东西
  不要被改动**，我们的固定尾块全是这一类。
- **设计型否定 —— 实测无效，脚本报 ERROR**：用"不要 X"去定义"要什么"。

**所以朝向、景别、姿态一律不许写在这里。** 历史上
`ep03_镜03` 的尾块写了 `顾万通正面朝镜头`、`刘兰站姿直立不前倾`，
`ep03_镜10` 写了 `苏慧低头含胸`、`位置左右互换`——这些全都没拦住，
因为否定句只是把"正面朝镜头"这个概念又注入了一遍。这些意图现在有
`camera_relation` / `body_dir` / `framing.*` 这些正向枚举承载。

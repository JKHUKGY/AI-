# 单图可控视频

交付可查看的证据链：原图 → 控制素材 → 实际模型输出 → 审查结果。用户仅要求研究时只出报告；要求 demo 时推进至可运行演示和已授权的生成。一次操作、一次模型推理和首轮高质量通过是三种不同承诺。

## 定范围与选路线

沿用会话中的素材、模型、预算和授权，不重复询问已确定事项。没有指定素材时，可选仓库现有已选图做独立试拍，记录来源，避免改动正式剧集。

先写简短情境与可观察的验收标准，再写生成提示词；新技术 demo 可以原创情境，明确它不是原剧本摘录。

按目标读取 [路线与官方依据](references/routes.md)：

| 镜头主要需求 | 优先试法 |
|---|---|
| 空场小幅运镜、需要远近视差 | 单图估深 → 2.5D点云重投影 → 深度控制 |
| 人物或物体沿画面路径移动 | 轨迹控制；复杂肢体动作换骨架/动画 |
| 多人走位、接触、遮挡关系 | 简化3D场景和带骨架替身 → 深度或姿态序列 |
| 大角度探索静态环境 | 场景生成/补全；验收未知区域后再渲染 |
| 镜头顺序、节奏或视频动作参考 | 支持相应模式的参考视频模型，例如H3 Ref2VA |

不要将“支持参考视频”解释成“支持逐帧深度控制”；不要把单物体网格、场景高斯、完整可动画角色混为一种资产。

## 制作最小控制素材

本包有可执行的纯CPU深度与2.5D小运镜示例。读取 [运行与实验](references/experiment.md) 后，建立项目内隔离依赖环境，执行：

```bash
python SKILL_DIR/scripts/build_control.py --source INPUT.png --out DEMO_DIR
python SKILL_DIR/scripts/verify_bundle.py DEMO_DIR
```

`SKILL_DIR` 替换成本技能路径。默认 512×896、121帧、24fps，参数可调整；15秒示例相机文件和命令见运行文档；它只生成控制素材和重投影预览，不调用视频模型。

关键约束：

- 原图、准备后的首帧、原始相对深度、PLY点云、相机参数与来源散列分别保留。
- 相对深度没有真实米制尺度；假定焦距与距离映射写入记录。
- 深度片全程使用相同归一化，亮=近/暗=远需核对所选模型；避免逐帧归一化闪烁。
- 图像首帧与控制片的构图、分辨率、帧率、帧数匹配。预渲染深度直接走条件编码，不能再次当RGB去估深。
- 单图移出遮挡会露出缺失区；保留覆盖掩膜与缺口比例。最近邻补洞只是预览填充，不能称为恢复了隐藏几何。
- 原图视角之外的生成补全、人物骨骼和动作需单独制作与验证，不能由本示例自动推断为已完成。

## 接入模型并验证

只读核对当前代码的真实接口和 checkpoint；版本易变，执行前以官方代码、模型卡和实际 `--help` 为准。[路线文档](references/routes.md) 给出发现入口，不把历史参数当永远有效。

本仓库已有 `short-drama-video-gen`、`short-drama-ltx-export`、`short-drama-ltx-generate`：用其镜头卡装配、基础校验和GPU生命周期管理。H3对应其 export/generate 技能。新控制输入由独立实验提交器承接，不把无法传递的字段写进旧 job 就声称生效。没有这些技能的宿主，根据官方接口建立等价执行器并保留提交清单，不假设缺失依赖存在。

若要求真实生成，核对账号、显卡和模型条款可用性；遵守当前授权与宿主边界。仅研究或只做预览不启动计费资源。资源不足时完成可做的控制素材并准确报告阻碍，不能将预览冒充成片。

默认先做一个镜头的一对实验：A首图+文字；B同首图同文字加控制。尽量匹配 seed、时长、分辨率、基础模型和采样方式，披露不能匹配的 pipeline/适配器差异。每路先只保留一次成功输出；技术失败也登记。要估成功率，需要更多预先选定镜头和种子，不能用一个好看的样例代替统计。

实际出片使用独立 Generator 和 Reviewer：Generator负责提交、下载和运行证据；Reviewer对照原创情境/原剧本、原图和控制预览验收，不只按生成prompt判分。复用 `loop-video-generation` 可用规则；生成与审查不能由同一个agent假扮两个角色。

重试需有具体可修原因并保留首轮结果。默认每路最多3次生成尝试，用户更小上限优先；到上限或预算截止就停止，报告未解决问题。单个对照实验不因结果不好擅自扩大为整集。只关闭本任务创建/明确接管的实例；已有生产实例需避免干扰。已租实例的主动收尾与超时兜底必须真实验证，保留停止状态；存储卷另计费。

本地watchdog依赖宿主会话存活，不能称为平台级关机保障。主动finally收尾后，再查询平台状态确认；会话中断恢复时先检查是否残留计费实例，再做其他工作。

## 审查与交付

按 [实验验收](references/experiment.md) 检查空间视差、运动方向、物体同一性、局部变形、闪烁、首尾状态。人物任务另查脚底滑动、关节、身份、接触与遮挡；本轮没有人物就不能给人物能力背书。

报告区分官方能力、代码核对、控制素材实测、AI成片实测。说明成本、生成次数、失败与局限。不要把首帧约束解释为所有后续帧在数学上被锁死；不要把放大/插帧等同于修复错误动作。

交付报告和一个无需读日志的观看入口，里面区分输入图、几何预览、控制视频、AI结果；缺失结果明确标注，不能伪造通过状态。附可复现源卡、参数、代码/模型版本、审查与成本记录。用户希望下次复用时保留技能脚本，避免复制机器特定的IP、卷ID、密钥或旧账号路径。

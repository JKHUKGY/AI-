# 关键帧提示词组装指南

`ep0X.md` 分镜表里的"图像生成提示词"列通常是简写（比如"复用苏晚(落魄期
立绘)跪地伸手动作+SC01背景"），不是能直接丢给出图工具的完整提示词。这一步
要把简写展开成完整 job，同时收集真正的参考图文件路径。

## 第一步：查文件路径，不要凭印象编

- 去 `short-drama-image-gen` 产出的 `selected.md` 里，按简写提到的"角色名+
  造型/表情"或"场景编号+版本"查到对应的**选中文件路径**。
- 如果 `selected.md` 里查不到对应的差分（比如分镜要的表情差分当时没生成），
  停下来告诉用户缺哪张素材，不要在没有对应基准图的情况下让模型凭文字
  瞎猜这个角色长什么样——那样会破坏已经建立起来的角色一致性。
- 场景要注意日/夜/版本匹配：`ep0X.md` 的"场景"列如果写了 `SC06(夜)`，要去
  `selected.md` 找夜版那一条，不要拿日版顶替。
- **场景还要匹配「机位」列**（2026-09 新增）：`ep0X.md` 每一镜都标了机位
  （`A主机位`/`B反打`/`C侧机位`/`D细节`），要去 `selected.md` 找**该场景该机位**
  那一行的底板，不能拿同场景别的机位顶替。以前没有这个维度，结果**同一场景所有
  镜头都用同一张 `_00.png`**——《出狱后》ep01+ep02 共 73 条 job，场景参考图
  73/73 全是 `_00`，于是整场戏从一个视角演完，只有景别（裁切松紧）在变。
- **要的机位在 `selected.md` 里查不到，就停下来告诉用户缺哪个机位，不要现编
  背景、也不要用别的机位顶替。** 这条以前被违反过两次：
  - `ep09.md` 镜2 要 `中景(俯拍视角)` + `SC03二楼走廊背景`，资产库没有，被降级成平视。
  - `ep02_镜11`（S 级镜）要厨房，没有对应 SC，那条 job **完全没传场景参考图**、
    靠文字现编了个厨房，却还留着自相矛盾的 `避免：场景背景与参考图不符`。
    真的没有场景参考图时，`避免` 里就不该写"与参考图不符"这种句子。

## 第二步：组装 prompt 文本

结构：`[画风锚点]` + `[本镜的画面描述/构图要求，展开自"画面描述"和"景别"
两列]` + `[必要时的合成说明]` + `[反面提示词]`。

- 画风锚点从 `characters.md`/`scenes.md` 开头抄一遍（应该和之前出角色/场景
  图时用的完全一致，不要重新措辞）。
- 把"画面描述"列的动作/表情原文转成更具体的构图指令，并结合"景别"列明确
  取景范围，比如画面描述是"苏晚跪地伸手去捡"、景别是"特写"，展开成"特写
  镜头，聚焦手部与散落衣物，人物跪地伸手的动作瞬间，构图突出手部颤抖细节"。
- 如果这一镜要合成"人物+场景"（大多数镜都是），在 prompt 里明确写一句
  "参考图1为本镜场景背景，参考图2为本镜人物，请将参考图2的人物自然地放入
  参考图1的场景环境中，保持人物面部特征、发型、服装与参考图2完全一致，
  保持场景背景与参考图1完全一致"——这句"保持一致"的指令比堆砌形容词更
  能防止模型在合成时"重新设计"了人物或场景。
  **注意这句里的"参考图1"必须是本镜「机位」列指定的那张底板。** 指令本身是对的、
  要留着，但它会把这一镜**硬锁**在参考图那个视角上——所以传错机位的代价是这一镜
  彻底没救，不是"稍微偏一点"。
- **人物在画面里的左右位置要照 `scenes.md` 的「空间关系」摆，反打机位要翻转。**
  A 机位下 X 在画面左、Y 在画面右，那么 `B反打` 这一镜里 X 必须在画面右、
  Y 在画面左，视线方向同时反向。分镜表「画面描述」里的（画面左侧/右侧）标注
  跟「机位」列对不上时先回去问，不要自己挑一个。
- **正反打要当两个机位分别出图，不要拍平成一个双人镜。** 历史上
  `ep01_镜06`（分镜写 `近景(单人正打+反打)`）被展开成 `近景双人构图…画面同时
  呈现两人的反应对比`，`ep02_镜08`（`近景(正反打)`）同样只出了一个视角——
  正反打的意图就这样丢了。
- 多人物同框：每个需要清晰呈现的角色各给一张参考图（`ref_images` 里按顺序
  排好，prompt 里对应写"参考图2为角色A，参考图3为角色B"），背景/群演角色
  按分镜表备注用文字描述简化处理，不单独找参考图。
- 反面提示词沿用角色/场景提示词模板里通用的一条，再按需加一句本镜特有的
  （比如"避免：人物表情与参考图不符、场景细节与参考图不符、多余人物"）。

## 第三步：组成 jobs.json

沿用 `short-drama-image-gen` 的 `jobs.json` 格式（见该 skill 的
`references/jobs_schema.md`），`id` 建议用 `ep{集号:02d}_镜{镜号:02d}`，
比如 `ep01_镜01`、`ep01_镜11`。`ref_images` 按上面收集到的场景图+人物图
路径填，`count` 默认 2-3（关键帧是"确认能不能用"，不需要像基准立绘那样
一次出很多变体）。

## 关于运镜/时长

关键帧图只是**这一镜的静态起始画面**，不需要在 prompt 里体现"推/拉/摇/移"
这些运镜信息（那是后续图生视频阶段动效提示词的事，不是这张图本身要表现的
内容），也不需要体现镜头时长。

**但「机位」不是运镜，它必须体现——而且是通过选对底板体现的，不是靠文字。**
运镜是这一镜内相机怎么动（下一步的事），机位是相机站在房间哪个位置（这一步的事）。
实际产出里出现过把机位当运镜写进 prompt 的情况（`全景镜头(缓慢横摇)`、
`近景镜头(骤然推进)`），那些括号里的文字对一张静态图没有意义，真正决定视角的是
**你传了哪张场景底板**。`ep0X.md` 里的"运动描述"列留给下一步（图生
视频）用，这一步先把静态关键帧做对就行。

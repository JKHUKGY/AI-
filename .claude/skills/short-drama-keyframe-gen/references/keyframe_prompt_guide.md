# 素材查找与卡字段对应指南

2026-09 改版：这一步**不再手写提示词**。提示词由
`scripts/build_keyframe_prompt.py` 从 `keyframe_cards.json` 机械装配
（字段见 `keyframe_card_schema.md`，走位规则见 `blocking_guide.md`）。
这份文档只剩两件事：**素材路径怎么查、查不到怎么办**，以及**分镜表哪一列
填到卡的哪个字段**。

## 一、查文件路径，不要凭印象编

- 去 `short-drama-image-gen` 产出的 `selected.md` 里，按"角色名+造型/视图"
  或"场景编号+时段+机位"查到**选中文件路径**，填进卡的 `plate_image` /
  `people[].ref_images`。
- 查不到对应的差分（分镜要的表情/视图当时没生成），**停下来告诉用户缺哪张**，
  不要在没有基准图的情况下让模型凭文字瞎猜这个角色长什么样——那样会破坏
  已经建立起来的角色一致性。脚本会检查路径存在性，编的路径过不了。
- 场景的查找键是**「SC 编号 + 时段 + 机位」三段**。`ep0X.md` 每一镜都标了
  机位（`A主机位`/`B反打`/`C侧机位`/`D细节`），必须取**该机位那一行**的底板。
  日/夜版本同样不许顶替（`SC06(夜)` 就去找夜版）。
- **要的机位查不到就报缺**，不要用同场景别的机位顶替、更不要不传场景参考图
  靠文字现编背景。以前被违反过：
  - `ep09.md` 镜2 要 `中景(俯拍视角)` + `SC03二楼走廊背景`，资产库没有，
    被降级成平视。
  - `ep02_镜11`（S 级镜）要厨房，没有对应 SC，那条 job **完全没传场景参考图**、
    靠文字现编了个厨房，却还留着自相矛盾的"避免：场景背景与参考图不符"。
  - ep01+ep02 共 73 条 job，场景参考图 **73/73 全是同一张 `_00.png`**，
    整场戏从一个视角演完，只有景别（裁切松紧）在变。

传错机位的代价不是"稍微偏一点"：装配出的提示词里有一句"保持相机视角与
参考图1完全一致"，它会把这一镜**硬锁**在底板那个视角上，所以底板错了这一镜
彻底没救。

## 一（补）、参考图只能来自 canonical 基准图，不许拿上一镜的产出当下一镜的参考

**硬规则：`people[].ref_images` 只能填 `selected.md` 登记的角色基准图
（三视图/表情差分），绝对不许填另一镜已经生成好的关键帧。**

理由是**漂移会累积**：A 生 B、B 生 C，三镜之后就是另一个人。业界共识的说法是
"never let one shot seed the next"——锁定一份 canonical 参考，把这一份接到
**每一个**下游节点上，而不是让镜头之间串行传递。

同理，`plate_image` 只能填场景机位底板，不能填"上一镜生成好的那张带人的图"。

唯一的例外是**分镜表备注明确写了"复用镜X"**的镜头——那种情况根本不重新生成，
直接把已有文件路径填进 `keyframes.md`，不涉及参考图。

## 二、分镜表 → 卡字段对应表

| `ep0X.md` 的列 | 填到卡的 | 备注 |
|---|---|---|
| 镜号 | `shot_no` / `id` | `id` = `ep{集号:02d}_镜{镜号:02d}` |
| 场景编号 | `scene` | |
| 机位 | `plate_id` | 再据此去 `selected.md` 查 `plate_image` |
| 出场人物 | `people[].name` | 顺序决定"参考图N"的编号 |
| 画面描述 | `beat_zh`（原文照抄，给人对照）+ 拆进 `people[]` 各字段 | 见下 |
| 景别 | `framing.shot_size` | 还要自己补 `subject_frac`/`crop_zh`/`plate_crop_zh` |
| 剧本原文锚点 | `script_ref_zh` | 阶段二验收的**唯一依据** |
| 分级 | `tier` | |
| 运镜 / 时长 / 台词 / 音效 / 转场 | **不进这一步** | 图生视频阶段的事 |
| 运动描述 | 只取"起始：…"那一句 → `posture_zh`/`action_zh` | 关键帧画的是运动的**起点** |
| 备注 | `notes` | 里面的越轴核对/复用说明要读 |

### 「画面描述」列怎么拆进 `people[]`

分镜表的画面描述通常是一整段散文，里面已经埋了走位信息，逐条挑出来：

> 刘兰（**画面左侧**，原坐在转角沙发朝北那一段）双手一撑猛地站起、朝画面
> **右前方**快步迎上两步，眉毛拧起、下巴前伸，**视线直盯着顾万通的脸**，
> 右手还捏着一只没放下的酒杯；顾万通（**画面右侧近端**，刚甩完包站定、
> **侧背对镜头**）胸口起伏、只把脸略微转向她，**视线仍看向画面外的地面**

拆成：

- `pos_x`：刘兰 `left`、顾万通 `right`（散文里的"画面左侧/右侧"）
- `depth`：顾万通 `near`（"近端"），刘兰 `mid`——**散文没写的那个人要自己
  定，不能让两人同层**，见 `blocking_guide.md` 规则二
- `body_dir`：刘兰 `screen_right`（"朝画面右前方"）、顾万通 `screen_left`
- `camera_relation`：顾万通 `three_quarter_back`（"侧背对镜头"）；
  **刘兰这一项散文里没有**，要自己定，这里定 `three_quarter_front`
  （她是这一镜要看表情的人）
- `gaze_at`：刘兰 `顾万通`、顾万通 `off_down`（"画面外的地面"）
- `posture_zh` / `action_zh`：站起前倾的**那一个瞬间** + 手里的酒杯 + 表情

**散文里没明说的字段就是这一步真正在做的设计**，也正是上一版全部漏掉、
结果被模型用默认值（正脸、同层）填上的地方。

散文里的（画面左侧/右侧）标注和「机位」列对不上时**先回去问**，不要自己
挑一个——`scenes.md` 的四向速记（"A 看北 → 左=西/右=东；B 看南 → 左=东/
右=西"）是判据。

### 正反打要当两个机位分别出两张卡

分镜表写 `近景(单人正打+反打)` 或 `近景(正反打)` 的镜头，是**两张卡**，
不是一张双人卡。历史上 `ep01_镜06` 被展开成"近景双人构图…画面同时呈现
两人的反应对比"，`ep02_镜08` 同样只出了一个视角，正反打的意图就这样丢了。
两张卡之间脚本会做越轴检查。

### 多人同框

每个需要清晰呈现的角色各给一张参考图（`people[].ref_images`，顺序就是
提示词里"参考图N"的编号）。背景/群演按分镜表备注用文字简化处理——写进
某个人的 `posture_zh` 里（"画面左侧虚焦处能看到沙发上另两人的身影轮廓"），
不单独占一个 `people[]` 条目、不给参考图。

## 三、反面提示词

Codex CLI 的 `image_gen` 没有独立的 negative prompt 参数，"避免"只能写进
prompt 尾块——装配器会自动补一条固定的通用尾块，`avoid_extra_zh` 只加本镜
专属的。**朝向/景别/姿态一律不许写在这里**（脚本报 ERROR），理由见
`keyframe_card_schema.md` 最后一节：ep03 那批用否定句写走位，一条都没拦住。

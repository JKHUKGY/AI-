# jobs.json 格式说明

`scripts/generate_images.py` 的输入是一个 JSON 数组，每个元素是一个"生成
任务"。由 Claude 在动手生成之前，读 `characters.md` / `scenes.md`（或用户
直接给的提示词），把里面的占位符（如 `[对应造型服装描述]`、`[画风锚点]`）
替换成具体文字后组装成这个文件——脚本本身不做任何 markdown 解析。

## 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 任务标识，会作为输出子目录名和文件名前缀。角色用 `角色名_造型_三视图`，场景用 `场景编号_名称[_时段][_机位]` —— **机位后缀是 2026-09 新增的必要槽位**，比如 `苏晚_落魄期_三视图`、`SC03_客厅_夜晚版_A主机位`、`SC04_餐厅_B反打`。单机位的过场场景可省略机位后缀保持现名（`SC13_顾家别墅门外`）；**多机位场景一律带后缀**，否则同一地点的几个角度会互相覆盖、或退化成只有一个角度（这正是 2026-09 之前的真实状况：所有场景资产只有一个摄影机位置，整场戏从一个视角演完）。机位词表 `A主机位/B反打/C侧机位/D细节` 见 `short-drama-storyboard/references/scene_prompt_template.md`。 |
| `prompt` | 是 | 完整的最终提示词文本，画风锚点、角色描述等占位符必须已经替换成具体内容，不要留 `[xxx]` 方括号占位符进这个文件。角色的 prompt 必须包含"三视图/turnaround"描述（同一张图里正面+侧面+背面并排、同一站姿同一服装、纯色背景），不要写成单一视角的"正面全身像"。 |
| `count` | 否，默认 3 | 这一任务这一轮要生成几张变体。角色三视图**固定生成 3 版**（除非用户明确要求增减）；场景**每个机位**首轮建议 2-4 张，够挑一张能用的；追加生成的返工轮次可以设小一点。⚠️ **`count` 是质量彩票，不产生机位**——同一条 prompt 出 4 张只会得到四张同视角的 seed 变体。历史教训：《出狱后》SC03 的场景档案明确要求"一次性生成 2-3 个机位角度（正面全景、沙发区中景、挑空楼梯俯瞰角度）"，实际提交的是**一条 prompt + `count: 4`**，拿回四张同视角变体，机位的意图就这样丢了（`selected.md` 最后只登记 `_00`）。**要 N 个机位就写 N 条 job**，每条一个机位后缀 + 一段自己的机位描述。 |
| `ref_images` | 否 | 参考图片的本地文件路径数组。角色三视图是该角色的第一份基准资产，通常留空走纯文生图；只有后续按分镜临时生成某个具体角度/表情，需要保持"同一张脸"时，才把已选定的三视图路径填进来。留空数组表示纯文生图。**场景机位组的规则见下方专门一节。** |

## 示例


## 场景机位组的 `ref_images` 规则（2026-09 新增）

- **`A主机位`** 是这个地点的定场/总览底板，**不需要参考图**，直接从陈设描述出图；
  但 prompt 里必须写明相机位置/机高/朝向，并要求"画面同时看清出入口、窗户和主要家具的
  相对位置关系"——它同时是后面派生其他机位的参考图和「空间关系」文字的视觉依据。
- **`B反打` / `C侧机位` / `D细节` 必须把 A 的选中图传进 `ref_images`**，
  prompt 里明写"这是同一个房间，相机移到……"。绝不允许只靠文字重新生成一个房间：
  同角度只换光影都已经漂过（`output/千金归位/assets/selected.md` 记录：
  "SC06 车道日/夜版建筑外观不一致：夜版是欧式石材豪宅，日版是现代极简风建筑，非同一栋房子"），
  换角度风险更大。
- 派生机位的 prompt 有三条硬要求，缺一条就容易生成成另一个房间：
  1. **点名要一致的具体物件**（"同一盏多层水晶吊灯、同样的黑色大理石桌面、同一批深灰皮质餐椅"），
     不要只写"保持场景一致"。
  2. **点名左右关系的翻转**：A 机位在画面右侧的门洞，从 B 反打看必须在**画面左侧**。
     这条既是给模型的指令，也是下游越轴检查的依据。
  3. **写清这个角度新露出来的东西**（反打会看到 A 机位身后的玄关/另一面墙），
     不写模型就会自己编，编出来的往往和房间风格打架。

留存粒度是**场景 × 时段 × 机位**，每一格留最终选中的 1 张。

```json
[
  {
    "id": "苏晚_落魄期_三视图",
    "prompt": "现代都市短剧写实照片级质感，电影感打光，竖屏9:16构图，主色调金属冷灰与暖金色交替，无水印无文字 + 一名24岁东亚女性，黑长直发前期略毛躁自然垂落，深棕色瞳孔，肤色偏白略显疲惫，身材纤瘦挺拔，穿着洗旧的浅色针织衫+牛仔裤，眼神隐忍。角色设计三视图/turnaround sheet：同一张图内并排展示正面、侧面（3/4侧）、背面三个视角，三个视角保持同一站姿、同一表情、同一套服装，纯色干净背景，比例一致，高清细节。避免：多余肢体、手指数量错误、五官崩坏、水印文字、三个视角不是同一个人、三个视角比例不一致",
    "count": 3,
    "ref_images": []
  },
  {
    "id": "苏晚_归位日常_近景震惊表情",
    "prompt": "现代都市短剧写实照片级质感，电影感打光，竖屏9:16构图 + 同一位角色，近景肖像，表情为震惊，嘴微张、眼睛瞪大，其余发型服装保持与参考图完全一致。避免：多余肢体、五官崩坏、水印文字、与参考图不是同一张脸",
    "count": 2,
    "ref_images": ["output/千金归位/assets/苏晚_归位日常_三视图/苏晚_归位日常_三视图_00.png"]
  },
  {
    "id": "SC03_客厅_日间",
    "prompt": "现代都市短剧写实照片级质感，电影感打光，竖屏9:16构图 + 室内客厅场景，白色真皮沙发，落地窗自然光，壁炉，吧台摆放红酒杯，精致but略显冷淡的陈设，无人物，空镜头/场景原画，高清细节",
    "count": 3,
    "ref_images": []
  }
]
```

第二个例子（近景震惊表情）不是出图流程这一步要预生成的东西，而是后续
`short-drama-keyframe-gen` 按具体分镜需要时才临时生成的，这里只是示范
"拿三视图当 `ref_images`"的写法。

## 关于 negative prompt

Codex CLI 的 image_gen 工具没有独立的 `negative_prompt` 字段，"避免出现什么"要直接写
进 `prompt` 文本末尾（参照上面示例里的"避免：xxx"一句），不要在 jobs.json
里额外造一个字段指望脚本处理，脚本不会读取。

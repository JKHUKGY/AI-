# AI 短剧出图助手 (short-drama-image-gen)

承接 `short-drama-storyboard` 产出的人物/场景提示词之后的下一步：真正调用
Codex CLI（ChatGPT 账号登录，不需要 API key/开通计费）把提示词变成图片，而且
要对生成结果负责——多生成几组、实际看图挑选，不是调一次就算完工。

## 强制执行：至少四个独立 subagent

根据用户要求，本 skill 的实际出图与审查统一交给
[loop-picture-generation](../loop-picture-generation/SKILL.md)。每个获准执行的出图
批次至少四个不同的真实子代理，主代理不计入。默认两名生成者分担任务、两名审查者
分别逐张审图与核对连续性；仅一张任务时改为一名生成者和三名审查者，不额外出图。
生成者不能审自己的图；主代理负责卡片、调度和登记，不能代替生成或独立审查。
四个是累计参与数，实际同时运行数受宿主限制，可分批；记录真实 agent ID 及交付物，
不能把主代理、同一代理的角色切换或四个脚本进程算成四个 subagent。
本节替代下文旧的“主代理自己生成／自查”和“可选多代理”执行方式，其余素材、
提示词装配与验收要求沿用。调用脚本的示例交给 Generator 执行，逐张和场次验收交给
不同 Reviewer 执行。每轮1→2→3、每项最多三轮，继承已有次数；到限失败项停止并报告，
继续获准且不依赖失败项的任务。已有用户确认有效；修改skill不等于新增生成授权或重置轮次。

## 0. 先确认输入和环境

- 输入优先用 `short-drama-storyboard` 产出的 `characters.md` / `scenes.md`
  （里面已经有画风锚点、角色档案、提示词正文、需要的差分列表）。如果用户
  没给这两个文件，也没有故事/分镜，先确认要不要跑 `short-drama-storyboard`
  生成，不要在没有角色设定的情况下凭空出图。
- 如果用户是直接甩几句提示词让你出图（没有走分镜流程），可以直接进入
  第 2 步，把这些提示词当作零散 job 处理。
- 检查 Codex CLI 是否已登录（`codex login status`），没登录就参照
  `references/api_setup.md` 引导用户跑 `codex login --device-auth` 完成
  ChatGPT 账号登录（这一步必须用户自己在浏览器里完成，Claude 只能把链接
  和一次性代码报给用户，不能代劳）。
- 角色出图**默认只生成一版**三视图（`count: 1`），能用就直接选它作为该角色贯穿
  全剧的基准图；如果用户明确要求增减，可以调整这个固定值，但不要在没有
  要求的情况下擅自按"表情/造型"再拆更多轮次。场景图同样首轮1张，失败后第二轮2张、第三轮3张；已有用户明确指定的张数按其要求执行，不为人数或并发额外加图。

## 1. 把提示词组装成 jobs.json

### 角色：固定生成"三视图"，不再逐个差分拆 job

> **这条有官方背书，不是省事的土办法。** OpenAI 的图像提示指南推荐的角色
> 一致性流程就是：**先在纯色背景上生成一张基准角色图，之后所有场景都把这张图
> 原样当参考图**；并且明说"多视图的 character sheet 把身份和服装压缩进同一张
> 参考帧里，能强化跨轮次的一致性"。所以三视图既是我们的资产，也是官方推荐的
> 锚点形式。详见仓库根目录 `研究.md` §2.7。

读 `characters.md`，对每一个角色只建**一条** job，而不是按正面/侧面/背面/
表情/换装分别建 job：

- prompt 在角色档案描述之外，明确要求"同一张图内包含正面、侧面（或
  3/4 侧）、背面三个视角并排展示，同一站姿、同一表情、同一套服装，角色
  设计三视图/turnaround sheet，纯色干净背景，比例一致"这类三视图专属描述，
  而不是"正面全身像"。要写实就写 `photorealistic`，**不要写 `8k`/`高细节`/
  `大师作品` 这类质量咒**（【官方】列为反面写法，不产生质量），
  要质感就点名具体材质和光源。
- 把提示词里残留的 `[画风锚点]`、`[对应造型服装描述]` 等占位符替换成具体
  文字（`characters.md` 里已经写了画风锚点原文和每个角色的具体档案，直接
  拼起来即可，不要自己编新的设定）。
- 把角色提示词模板里的"反面提示词"（避免多余肢体/五官崩坏/水印文字、
  避免三个视角不是同一个人/比例不一致等）拼到 `prompt` 末尾。这些都属于
  **保留型否定**，官方推荐照写；**但不许用否定句去写朝向/姿态/景别**
  （"不要正面朝镜头"这种实测无效），规则见 `references/jobs_schema.md`
  「关于 negative prompt」一节。
- `count` 首轮固定填 1（一版三视图），`ref_images` 留空——三视图是这个
  角色的第一份基准资产，没有更早的图可以参考。
- 一个角色一套造型对应一条 job；如果故事里这个角色有多套明显不同的造型
  （比如"落魄期"和"归位日常"），每套造型各建一条三视图 job，`id` 用
  `角色名_造型_三视图` 命名，比如 `苏晚_归位日常_三视图`。
- 后续镜头里如果确实需要某个具体表情/动作的单独图，不在这一步预生成，
  等 `short-drama-keyframe-gen` 按分镜实际需要时，再拿这版选中的三视图当
  `ref_images` 现场生成，避免一开始就铺开一堆用不上的表情差分。

### 场景：按原逻辑，一个场景一个（或多个时段）job

读 `scenes.md`，对清单里需要出图的每一份场景/时段版本各建一条 job，占位符
替换方式和反面提示词处理方式同上。

按 `references/jobs_schema.md` 的格式写成一个 JSON 文件（比如
`output/<故事名>/assets/jobs_round1.json`）。一次不用把全剧所有资产塞进一
个 jobs 文件，可以按"这一轮先出哪几个角色/场景"分批组织。

### 要不要走并行模式：角色和场景同时出图

如果这一轮要出的角色三视图和场景图互相没有依赖（场景不需要引用某个角色
的三视图当 `ref_images` 保持人物一致性——这是最常见的情况），不需要顺序
"先出完角色再出场景"，可以拆成 `jobs_characters.json` / `jobs_scenes.json`
两个文件，由两名 Generator 分担，并由另外两名独立 Reviewer 审查；脚本内部也支持多个 codex 子进程
同时生成。具体怎么拆、subagent prompt 怎么写、并行度怎么选，见
`references/parallel_mode.md`；有依赖关系的场景 job（需要先选定角色图再
生成）不要塞进并行批次，留到角色选完后单独生成。

## 2. 调用脚本批量生成

```bash
python3 .claude/skills/short-drama-image-gen/scripts/generate_images.py \
  output/<故事名>/assets/jobs_round1.json \
  --out-dir output/<故事名>/assets
```

- 默认顺序执行（一张一张来）。想让多张图同时生成（多个 `codex exec` 子
  进程并发跑），加 `--parallel N`（比如 `--parallel 3`）；配合角色/场景
  两个 jobs 文件分别起两个 subagent 同时跑，就是"一键并行生成角色+场景"，
  完整做法见 `references/parallel_mode.md`，不要在没读过那份文档、不清楚
  并发上限的情况下自己瞎设一个很大的 `--parallel` 数值。
- 脚本只依赖标准库+已登录的 `codex` CLI，不需要额外装包、不需要 API key。
  实际调用的是 `codex exec` 内置的 `image_gen` 工具，选它的原因和怎么调整
  见 `references/api_setup.md`。竖屏构图（9:16）要写进 prompt 本身（`jobs.json`
  里的 `prompt` 字段已经带了画风锚点里的"竖屏9:16构图"一句，不需要额外的
  aspect-ratio 参数）。每个 job 的图片会落在 `output/<故事名>/assets/<job的id>/`
  下，文件名
  形如 `<id>_00.png`、`<id>_01.png`……重复调用同一个 job 会接着编号往后
  生成而不会覆盖已有文件。
- 生成过程中脚本会把每张图的信息追加进
  `output/<故事名>/assets/manifest.append.jsonl`（prompt、参考图、模型、
  时间戳），方便回溯"这张图当时用的什么提示词"。
- 如果 `codex exec` 报错退出、或目标文件反复没有生成，把报错原文给用户看，
  不要吞掉错误自己瞎猜原因；疑似限流或账号未登录时参照 `references/api_setup.md`
  的建议处理，不要无脑加大重试次数硬跑。

## 3. 实际看图验收，不是"生成了就完事"

由独立 Reviewer 对每个 job 新生成的图片，逐张用图片查看工具打开实际查看（图片路径直接传给
Read 即可当作多模态输入看到画面内容），按 `references/review_checklist.md`
的标准逐条判断：符不符合角色档案、五官肢体正不正常、构图对不对、有没有
水印、画风统不统一、情绪动作到不到位。角色的三视图 job 额外检查
`references/review_checklist.md` 里"三视图专属检查"一节——同一张图里
正面/侧面/背面是不是同一个人、比例是否一致。

给用户一个简短汇报：这一轮每个 job 生成了几张、选中了哪几张（文件名）、
淘汰了哪几张及原因。不要只说"已生成"而不说选没选出可用的。

## 4. 选不出可用图就调整后重新生成，多来几组

对没有选出合格图的 job：

1. 分析这一轮不合格的具体原因（比如五官总崩、颜色总是不对、三个视角
   明显不是同一张脸/比例不一致），把这个原因转成更明确的描述或加强的
   "避免：xxx"写回 `prompt`。
2. 角色三视图这一轮如果连一版都选不出来，直接重新生成整版三视图（同一
   条 job 追加 `count`），不要试图从某一版里"拆一个视角能用、拆一个视角
   不能用"去拼凑，三个视角必须来自同一版生成结果。
3. 追加一条新 job（或复用同一个 `id`，脚本会接着编号），角色三视图仍
   按加量阶梯重新跑（第 2 轮 `count: 2`、第 3 轮 `count: 3`），不要一上来就多出，避免一次性
   浪费太多调用次数，重新跑第 2 步。

按 `references/review_checklist.md` 的"何时停止重试"标准控制轮次——单个
job 连续 3 轮都选不出可用图就停下来问用户，不要自己无限重试下去。

## 5. 整理最终资产目录

角色：每个角色（每套造型）的实际生成候选里，最终留 1 版作为该角色贯穿
全剧的基准参考图；场景：留存粒度是**场景 × 时段 × 机位**，每一格留最终选中的 1-2 张（机位是 2026-09 新增的维度，`A主机位`/`B反打`/`C侧机位`/`D细节`，见 `references/jobs_schema.md`）。其余废弃
变体不需要删除（留着方便回溯），但要在 `output/<故事名>/assets/selected.md`
里列一张表登记最终入选清单：

| 角色/场景 | 造型/版本 | 选中文件路径 | 对应 characters.md/scenes.md 里的条目 |
|---|---|---|---|

角色这一行的"选中文件路径"就是那一整张三视图图片——后续分镜/关键帧生成
需要某个具体角度或表情时，直接把这张三视图当 `ref_images` 传给模型现场
生成，不需要在这一步预先拆好。这张表就是后续做分镜合成图、把关键帧交给
图生视频环节时要引用的"资产清单落地版"，呼应 `short-drama-storyboard` 里
"资产清单"这一步。

## 6. 汇报成本

结束时汇总：本次一共调用了多少次生成 API（可以直接数
`manifest.append.jsonl` 新增的行数），供用户记进
`short-drama-storyboard` 输出模板里的"成本与检查记录"。

## 与其他 skill 的衔接

- 上游：`short-drama-storyboard` 产出 `characters.md` / `scenes.md`。
- 下游：选定的图片路径会被后续"把关键帧丢进图生视频/剪辑"的环节直接引用，
  所以 `selected.md` 里的路径要准确、不要中途手动改文件名却不同步登记表。
- 本 skill 第1步组装完jobs之后，**必须**调用 `loop-picture-generation`
  执行第2–4步，使用至少四个不同的subagent完成生成和独立审查。

## 人读与机器产物分开

按 [阅读目录约定](../loop-picture-generation/references/output_layout.md) 整理产物；完成本轮生成与验收后刷新给人看的分镜、图片和进度入口。

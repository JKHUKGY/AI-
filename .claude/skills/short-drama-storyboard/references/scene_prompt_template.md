# 场景/背景设计提示词模板

**一个地点不是一张图，是一组机位。**

这是 2026-09 的变更，也是这份模板存在过的最大缺陷：旧版规定"同一房间不同镜头尽量只生成
1-2 张背景图，用裁切/构图调整覆盖不同机位"。结果是每个地点只有一个摄影机位置，整场戏
从一个视角演完——同一个吊灯永远在正中、同一个门洞永远在右侧，只有景别（裁切松紧）在变。
实际拍出来的效果见 `output/出狱后我成为了非洲矿王/videos/ep02/_frames_check/`：
镜04 和镜07 是同一个餐厅的同一个机位，只是拉宽了。

更糟的是这个问题**被写下来过两次、实现过零次**——`scenes.md` 的 SC03 档案写了
"建议一次性生成 2-3 个机位角度"，复用建议写了"务必第一次生成时就做出2-3个机位角度"，
但下游没有任何字段能承载"机位"，于是意图停留在注释里，实际只出了一条 prompt。

所以这份模板现在把机位做成**结构化字段**，不再是建议。

---

## 场景档案

- 场景编号/名称（对应场景清单）：
- 出现集数：
- 室内/室外：
- 时间/天气（白天/夜晚/黄昏/雨天等，只在剧情需要变化时才拆分）：
- 氛围/情绪关键词（比如"压抑""温馨""紧张对峙"）：
- 关键陈设/构图元素（会在多个镜头里反复出现、必须跨机位保持一致的背景细节）：
- 光影/色调设定（呼应本场景情绪基调，与角色提示词的画风锚点色调呼应）：
- **场景重要度**：主场景 / 次场景 / 过场场景（决定出几个机位，见下）
- **机位组**：本场景要出哪几个机位（见下表）

---

## 一、机位词表（固定四档，不许自创）

| 机位 | 定义 | 怎么出 |
|---|---|---|
| `A主机位` | **定场/总览**。最宽，**必须同时看清出入口、窗户和主要家具的相对位置** | 从陈设描述直接出图，不需要参考图 |
| `B反打` | A 的反向 ~180°、同机高 | **以 A 当 `ref_images`**，明写"同一个房间从相反方向看" |
| `C侧机位` | A 右转 ~90°、同机高 | 同上 |
| `D细节` | 更近 / 俯或仰 / 道具局部 | 同上 |

`A主机位` 一图三用：**它自己就是可拍的定场镜、是派生 B/C/D 的参考图、也是下面「空间关系」
那段文字的视觉依据。** 所以不需要另外再出一张"只当锚点用"的总览图。

## 二、机位组预算（按场景重要度分级）

| 场景重要度 | 判断依据 | 机位组 |
|---|---|---|
| **主场景** | 跨集复用，或一集里镜头数很多，或承载核心冲突 | `A + B + C + D` |
| **次场景** | 正常演一两场戏 | `A + B` |
| **过场场景** | 空镜/环境交代/时间流逝，不承载对话 | `A` |

参考量级：《出狱后》的 SC03 客厅跨 6 集、SC04 餐厅一集 12 镜，这两个是典型主场景；
SC08 丛林断崖只在第 4 集出现一次，是过场场景。

**时段不要和机位做笛卡尔积。** 日/夜/雨仍然只在剧情需要时才拆，而且**只给"该场景在该
时段实际出现的那几个机位"出图**。比如 SC06 矿场办公室日版要 `A+B`，夜版剧情只有"翻抽屉"
这一个动作，那夜版只出 `D细节` 就够，不必把四个机位在夜里重出一遍。

## 三、空间关系（**出完 A 主机位、实际看过那张图之后**填）

这一段是防越轴的唯一依据，也是下游选机位的地图。**必须用 Read 工具把 A 主机位的图打开
看一遍再填**，写图里真实的东西，不要凭 prompt 里的措辞想象——prompt 说"门洞在右侧"，
模型有可能给你放到左侧，那就按图里的实际情况写。

```
- 主轴（A 机位的视线方向）：
- 出入口/窗（相对 A 机位画面的位置）：
- 主要家具及朝向：
- 人物默认站位/座位（谁在轴线的哪一侧）：
- 各机位相对 A 的方位/机高：
```

填好的样子（餐厅）：

```
- 主轴（A 机位的视线方向）：从餐厅入口朝向落地窗，长桌纵深方向与主轴一致
- 出入口/窗：厨房门洞在画面右侧中景，落地窗在画面纵深端，玄关在画面外、相机身后
- 主要家具及朝向：黑色大理石长餐桌居中纵向，主位椅在纵深端，水晶吊灯在桌面正上方，
  左侧靠墙边柜上有暖黄台灯
- 人物默认站位：顾万通坐主位（纵深端），刘兰坐其右手侧，顾浩/顾瑶坐画面左侧长边，
  苏慧站在画面右侧厨房门洞附近
- 各机位相对 A：B反打 = 从落地窗朝入口方向看（同机高）；C侧机位 = 从长桌右侧长边看
  （同机高）；D细节 = 桌面高度俯 30°，只拍桌面和手
```

## 四、提示词正文（**每个机位一条**）

### `A主机位`

```
[画风锚点，与角色提示词共用同一句] + [室内/室外]场景，[地点]。
【机位】定场主机位：相机架在[位置]、[机高]、正对[朝向]，广角收全，
画面必须同时看清房间的出入口、窗户和主要家具的相对位置关系。
【陈设】[关键陈设，逐件写清相对位置]。
【光影】[光影/色调描述]，[氛围关键词]。
无人物，空镜头/场景原画，高细节，8k画质。避免：出现人物、水印文字、真实品牌LOGO
```

### `B反打` / `C侧机位` / `D细节`（`ref_images` 必须传 A 主机位的选中图）

```
[画风锚点] + 参考图1是这个房间的定场机位。
【机位】这是**同一个房间**，相机移到[相对 A 的方位]、[机高]，朝[朝向]看。
【必须一致】陈设、材质、色调、光源位置与参考图1完全是同一个房间：
[逐件点名从这个角度应该看到的东西，以及它们相对画面的左右位置]。
【这个角度新看到的】[A 机位看不到、这个角度才露出来的东西]。
【光影】[同一套光源，但从这个角度看到的明暗分布]。
无人物，空镜头/场景原画，高细节，8k画质。避免：出现人物、水印文字、变成另一个房间、
陈设或材质与参考图1不一致
```

**写 B/C/D 的三条硬要求**：
1. **点名要一致的东西**，不要只写"保持一致"。写"同一盏水晶吊灯、同样的黑色大理石桌面、
   同样的暖黄台灯"，比写"保持场景一致"有用得多。
2. **点名左右关系**。B 反打是 180° 转过来，A 机位在画面右侧的门洞，从 B 看必须在画面左侧。
   这条写进 prompt，也是后面越轴检查的依据。
3. **写清这个角度新露出来的东西**。反打机位会看到 A 机位身后的空间（玄关、另一面墙），
   不写模型就会自己编，编出来的往往和房间风格打架。

如果要"人物+场景"合成的分镜关键帧图（而不是纯背景底板），那是
`short-drama-keyframe-gen` 的事，在这里定好的机位底板上合成，不要在这一步做。

## 五、复用与留存

- **留存粒度是「场景 × 时段 × 机位」**，每一格留最终选中的 1 张，登记进 `selected.md`
  （那张表现在有 `机位` 列）。
- `count` 是**质量彩票**，不是机位。同一条 prompt 出 3 张是为了挑一张能用的，
  **`count: 4` 不会给你四个角度**——这是旧流程最大的误解来源：《出狱后》SC03 的档案
  要了三个机位，实际提交的是一条 prompt + `count: 4`，拿到四张同视角变体。
- 建立"场景原画库"，每张图标注机位、对应的提示词版本和适用镜号范围，方便后续分集复用、
  也方便发现"这个机位其实还没生成过"的遗漏。
- **分镜表要了某个机位而资产库里没有，是要报缺的，不是要用别的机位顶替。**
  `ep09.md` 镜2 要 `中景(俯拍视角)` + `SC03二楼走廊背景`，资产库里没有，
  历史上这一镜被无声降级了。现在的规则是停下来告诉用户缺哪个机位。

## 六、跨机位一致性的已知风险

同一个房间从不同角度生成，最大的失败模式是**生成成"几个不同的房间"**。这不是理论担忧，
`output/千金归位/assets/selected.md` 已经记了一条同类故障：

> SC06 车道日/夜版建筑外观不一致：夜版是欧式石材豪宅，日版是现代极简风建筑，非同一栋房子

那还只是换光影就漂了，换角度的风险只会更大。所以：

- B/C/D **必须**把 A 的选中图传进 `ref_images`，绝不允许只靠文字描述重新生成一个房间。
- 出完一组机位要**逐张 Read 对答案**，判据见
  `short-drama-keyframe-gen/references/keyframe_review_checklist.md` 的跨机位一致性检查。
- 实测结论（成不成、怎样才成）记录在
  `short-drama-video-gen/references/model_capability_ledger.md`。

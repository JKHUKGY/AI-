# Reviewer agent（审查 agent）

## 职责边界

只做一件事：拿到 Generator agent 这一轮抽出来的帧，用 Read 工具逐张实际
打开查看，判断这一轮生成的视频有没有问题，给出结构化 verdict。**不负责
提交生成，不负责决定要不要重试**（重试轮次上限由 orchestrator 按
`round_count` 强制执行）。

## 判断依据：刻意不用分镜表原文，改用 script_ref

这是本 skill 跟其它验收流程最大的区别，必须在 prompt 里明确讲清楚：
`ep0X.md` 分镜表"画面描述"那句话已经是生成这一轮视频时用过的输入（写进
了 `prompt` 里），拿它当验收标准等于自己出题自己判卷——任何"字面关键词
都对上了"的生成结果都会被无脑判 `pass`，哪怕实际情节/情绪完全没讲对。

Reviewer 唯一的判断依据是 unit 的 `script_ref`（原剧本/分集大纲里对应这
一段实际场景的原文），要回答的问题是："这段视频有没有让人看懂/感受到
`script_ref` 里描述的这个情节点"，不是"这段视频有没有出现分镜表里写的
那几个关键词"。

## 判断标准

### 一、情节/情绪吻合度（对照 script_ref，不是分镜表）

- 这段视频呈现的场景、人物状态、情绪走向是否符合 `script_ref` 描述的这个
  情节点，观众看这段视频能不能获得 `script_ref` 想传达的感受。
- 如果视频技术上很流畅、人物没崩坏，但呈现出来的情绪/状态跟 `script_ref`
  南辙北辙（比如 `script_ref` 要的是"隐忍的委屈"，视频却呈现出"面无表情
  的呆滞"），仍然判 `fail`，不能因为"技术上没毛病"就放过。

### 二、视频生成特有的技术问题

- **背景变换**：背景在过程中有没有跑偏、闪烁、突然变成另一个场景/时段、
  跟首帧确立的场景不连贯。发现这类问题先怀疑 `prompt` 是不是把首帧图里
  已经有的静态内容（人物穿着、发型、背景陈设）又用文字重新描述了一遍——
  `ltx_pipeline_gotchas.md` 记录过这是图生视频常见的坑：文字复述会跟
  "图像条件"打架或被模型忽略，导致背景/外观跟着文字跑偏；`fix_instruction`
  应该先建议把这类复述从 `prompt` 里删掉、只保留动作/表情/镜头变化的描述，
  而不是急着说"加强负面提示词"（见下面"真正生效的修改杠杆"）。
- **人物/动作生成**：人脸/发型/服装在动作过程中有没有崩坏、悄悄"换了张
  脸"、肢体拉伸扭曲、多余或缺失肢体、动作方向跟预期相反（该低头却抬头）。
- **视角/景别**：镜头视角、取景范围是不是跟这一镜设计的运镜/景别一致，
  有没有莫名其妙的镜头切换、异常抖动、视角跳变。
- **首尾帧衔接**：首帧是否还是原关键帧的样子；如果指定了尾帧，结尾是否
  落在预期的定格姿态。
- 以上这几条的具体检查手法（怎么抽帧、逐帧看什么）沿用
  `short-drama-video-gen/references/video_review_checklist.md`"逐帧核对"
  一节，这里不重复列细则，只强调判断的"标的"从分镜表换成了 script_ref。

### 真正生效的修改杠杆（`fix_instruction` 只能落在这几项上）

`ltx_ssh_submit.py` 已经确认 `ltx_pipelines.distilled`/`dfr_pipeline`
**都没有 `--negative-prompt` 这个 CLI 参数**——改 `negative_prompt` 字段
对生成结果没有任何实际影响。`fix_instruction` **不允许**只写"加强负面
提示词"就交差，必须落在下面这几个真正会改变生成结果的地方：

1. **正向 `prompt` 的文字本身**——尤其检查是否复述了首帧已有的静态内容
   （见上面"背景变换"一条）、描述是否前后矛盾（比如同时写"缓慢推进"和
   "固定机位"）、动作幅度的形容词是否需要换成更克制的说法。
2. **`seed`**——如果画面里的问题看起来是"这次随机采样运气差"（比如同一
   套动作描述、上一轮某个局部细节崩了，其余都正常），换一个新的 `seed`
   值往往比反复重写 prompt 更有效；如果问题是"系统性的"（比如每一轮都在
   同一秒出现同一类崩坏），才应该优先改 prompt 而不是换 seed。
3. **分段/首尾帧**——长动作或多阶段动作按 `stability_playbook.md` 拆成
   更短的分段，或者补一张更明确的尾帧控制结束状态。
4. **局部重绘（`defect_window`）**——如果问题**只集中在视频的某一小段
   时间窗口，其余画面完全正常**（比如"只有第2-3秒背景闪烁，开头结尾都
   没问题"），不要走整段重来，给出 `defect_window: {start, end}`（单位
   秒），orchestrator 会改用 `ltx_pipelines.retake` 只重绘这一段，省下
   重跑整段的显卡时间。如果问题影响了全片基调（比如首帧身份就错了、
   整体情绪从头到尾都不对），不要给 `defect_window`，走整段重来。

**注意：`ref_images` 不是有效杠杆**——`ltx_ssh_submit.py` 从不读取/上传
这个字段（详见 `units_schema.md`），`fix_instruction` 不能落在"补一张
参考图"上，一致性问题只能靠改 `prompt` 文字或换 `seed` 解决。

### 三、音画同步（提醒，不判断）

如果这一镜走了带音频的路线，跟 `video_review_checklist.md` 一样明确提醒
用户自己听一遍确认，Reviewer agent 不判断音节精确对齐。

## Agent 调用模板

Generator 返回后，发一次 Agent 调用，prompt 参照：

```
你是本轮 AI 短剧视频生成任务里"<unit.id>"这一个镜头的审查 agent。

这个 unit 唯一的判断依据（不要用 ep0X.md 分镜表"画面描述"列的文字代替，
那句话已经是这一轮生成时用过的输入，拿它当标准等于自己出题自己判卷）：
"""
<unit.script_ref 原文>
"""

这一轮生成的视频抽出的帧（用 Read 工具逐张实际打开查看，按开头/1/4/中间/
3/4/结尾的顺序）：
<帧图片绝对路径列表>

请依次判断：
1. 情节/情绪吻合度：这段视频有没有让人看懂/感受到上面 script_ref 描述的
   情节点，不要对照分镜表的字面描述。
2. 背景变换：背景有没有跑偏/闪烁/变成别的场景。
3. 人物/动作生成：人脸/服装/肢体有没有崩坏，动作方向对不对。
4. 视角/景别：镜头视角取景是否跟运镜设计一致，有没有异常抖动/跳变。
5. 首尾帧衔接：首帧是否还原关键帧，结尾是否落在预期定格姿态（如果有指定
   尾帧）。

严格按下面格式返回，不要输出这个格式之外的其它内容：

verdict: pass 或 fail
reason: <具体指出哪一条判断依据不满足，或者哪几条都满足，不能只说"还行"
  或"不够好">
fix_instruction: <只有 fail 才填。必须落在"真正生效的修改杠杆"（prompt
  文字/seed/分段/局部重绘）里，能直接落实成下一轮生成参数改动的一句具体
  描述，比如"背景在第2秒开始明显变亮变成了另一个场景，prompt 里复述了
  '暖黄色灯光'这类首帧已有的静态描述，删掉这句只保留动作变化描述，并换
  一个新 seed 重试"，不能写"加强负面提示词""补一张参考图"或"再改进一下"
  这种对这个 pipeline 不生效/没法执行的话>
defect_window: <只有问题局限在一小段时间窗口、其余画面完全正常时才填
  `{"start": 秒数, "end": 秒数}`；问题影响全片基调就留空，不要勉强凑一个
  窗口>

如果这已经是这个 unit 第 3 轮（累计 3 轮都没有 pass），额外加两行：
best_of_all: <这 3 轮里最接近可用的一版视频文件路径，并说明它还差在哪>
downgrade_suggestion: <是否建议把这一镜降级成 short-drama-video-gen 的
  ken_burns.py 纯运镜处理，简要说明理由>
```

调用前 orchestrator 需要告诉这个 agent 它现在是第几轮，这样它才知道要不
要在最后补 `best_of_all`/`downgrade_suggestion` 那两行。

## 判断标准里最容易出错的地方

- 不要因为"生成的画面很好看/很稳"就判 `pass`——好看但没讲对
  `script_ref` 描述的情节，仍然判 `fail`。反过来也不要因为"这镜情节很
  重要"就对明显的技术崩坏（换脸、背景闪烁）视而不见，两条标准都要过。
- `fix_instruction` 必须具体到"下一轮 Generator agent 不需要再猜"的程度，
  能直接对应到"真正生效的修改杠杆"里的某一项（改 prompt 文字、换 seed、
  拆段、局部重绘），写含糊的意见、或者落在不生效的 `negative_prompt`/
  `ref_images` 字段上，等于把问题又踢回给下一轮。
- 不要为了"省一次整段重来"硬凑一个 `defect_window`——如果背景闪烁其实
  从头到尾都有、只是某几秒更明显，那不是"局部问题"，老实判定成全片问题，
  走整段重来，`defect_window` 判断错了会让 retake 修出一段跟前后风格不
  连贯的补丁。

# 图生视频提示词组装指南

关键帧图已经锁定了人物长相、服装、场景——图生视频的提示词**不需要再重复
描述这些**，核心任务只有一件事：说清楚"接下来发生什么、镜头怎么动"。这一点
是 Runway 官方图生视频指南反复强调的："Effective image to video prompts
focus almost exclusively on motion"，堆砌外观形容词只会稀释动作指令的
权重，甚至让模型误以为要重新设计人物。

## 提示词公式

```
[动作分解：起始姿态(可省，关键帧已定) → 过程关键点1 → 过程关键点2(可选) → 结束姿态/定格]
+ [运镜：推/拉/摇/移/跟/固定，翻译自分镜表"运镜"列]
+ [节奏与速度：缓慢/克制 或 骤然/短促，配合分级]
+ [光影/氛围变化（如果本镜需要，比如"手机屏幕光在脸上忽明忽暗"）]
+ [负面提示词]
```

## 第零步：跨镜头连贯性核对（写 prompt 前先看邻镜，不要只盯着这一镜）

这是这一步最容易被跳过、也是实际返工率最高的问题来源：**只孤立地看当前
这一镜的关键帧和运动描述，不回头核对上一镜的结束状态、不确认下一镜的起始
需求**，结果就是同一场戏里前后两镜的姿态/位置/情绪衔接不上——比如上一镜
人物刚跪地痛哭，这一镜的提示词却把"起始姿态"写成站着说话，模型没有任何
线索知道这是"错的"，会老老实实按 prompt 生成一个和上一镜断裂的动作。

**写每一镜的 prompt 之前，先做这三件事**：

1. 回头看 `ep0X.md` 里同一场景段的上一镜"运动描述"结束姿态/定格描述（如果
   上一镜是 B/C 级没有运动描述，就看它的画面描述结尾状态），确认这一镜的
   "起始姿态"和它是同一个逻辑动作的延续，而不是凭这一镜关键帧本身的画面
   孤立编一个新起点。如果分镜表本身在 `short-drama-storyboard` 阶段已经
   按"跨镜头动作衔接"规则检查过，这一步通常只是确认，不需要重新设计；如果
   发现分镜表本身就没接上，停下来提醒用户回头补分镜，不要在视频提示词里
   "悄悄圆过去"掩盖分镜设计的断裂。
2. 看一眼下一镜的画面描述/起始状态需求，确认这一镜的"结束姿态/定格"写完
   之后，下一镜衔接得上（不需要下一镜也现在写，只是提前避免这一镜结束姿态
   和下一镜设定互相矛盾）。
3. 确认场景/光影/时间是否连续：同一场景段内的连续镜头，除非分镜表标注了
   转场（淡出淡入/时间跳跃），否则光照方向、天气、时段应保持一致，prompt
   里不要随手加一句和上一镜矛盾的光影描述（比如上一镜写"逆光昏暗"，这一镜
   却写"阳光明媚"）。

多人物同框的镜头额外核对：这一镜里每个人物的位置/朝向是否和上一镜他们各自
所在的位置连续（除非明确是正反打切换机位角度，而不是人物真的挪动了位置）。

## 第一步：把"运动描述"列展开成分阶段动作

`ep0X.md` 的"运动描述(S/A级需要)"列通常是一句简写（比如"她哭了"
"震惊后瘫坐在地"），照抄进 prompt 会让模型自己脑补一个不可控的完整动作。
按下面方法拆解：

1. **起始姿态**：确认这一镜开始时人物的姿势/表情/视线方向，并且要和第零步
   核对过的上一镜结束状态一致（这一步不能因为"就是关键帧本身的状态"而
   跳过不写——关键帧只锁定了外观，不代表模型知道"这个姿势是从哪个动作
   延续过来的"，写出来既是防止模型"重新摆姿势"，也是把跨镜衔接的逻辑显式
   传给模型）。
2. **过程关键点（1-3 个动词短语）**：把动作拆成几个具体的中间点，不要用
   笼统形容词。
   - 差示例："她哭了"（模型不知道哭到什么程度、多快、动作细节）。
   - 好示例："眼眶先泛红，睫毛轻微颤动，随后一滴泪水缓缓滑落脸颊，嘴角
     随之向下撇，肩膀轻轻抽动一下"。
3. **结束姿态/定格**：明确结束时停在什么状态，配合"定格感"手法——关键
   情绪瞬间让画面在结束前有 0.5-1 秒的停顿，比如"最后定格于泪水滑落
   下巴的瞬间，人物保持低头姿态短暂静止"。

动作幅度和镜头分级要匹配：

- **A 级（对话/反应镜，全集主体）**：只写小幅度动作——转头、抬眼、嘴角
  变化、手指轻微动作、呼吸起伏。幅度越小越稳，出错率最低。
- **S 级（打斗/拥抱/痛哭/反转瞬间）**：才值得写大幅度动作，同时要接受
  这类镜头需要更多轮生成、更值得花预算精修。

## 第二步：运镜描述翻译成自然语言指令

复用 `short-drama-storyboard` 的 `shot_grammar.md` 运镜词汇，翻译成该平台
能理解的自然语言（大多数平台现在都支持中文自然语言描述运镜，不需要额外的
参数代码）：

| 分镜表运镜 | 图生视频提示词写法示例 |
|---|---|
| 推 | "镜头缓慢向前推进，聚焦人物面部" |
| 拉 | "镜头缓慢向后拉远，逐渐露出周围环境" |
| 摇（左/右/上/下） | "镜头缓慢向右摇镜，跟随人物视线转移" |
| 移 | "镜头随人物走动方向水平平移" |
| 跟 | "镜头跟随人物奔跑方向移动，略带手持晃动感增强代入感" |
| 固定 | 不写运镜描述，或明确写"镜头固定不动"防止模型自作主张加运镜 |

节奏副词按分级选：S 级用"骤然/猛烈/快速"强化冲击感，A 级用"缓慢/轻微/
自然"保持稳定不崩。

## 第三步：负面提示词模板

在正向提示词末尾（或该平台单独的负面提示词框）加上：

**通用负面（各平台通用）**：
```
避免：人物面部变形、五官错位、多余或缺失肢体、手指数量错误、肢体拉伸扭曲、
镜头剧烈抖动、画面闪烁跳变、人物中途换脸、模糊、低质量、水印、字幕、
多余人物入镜、色调突变
```

**短剧场景特有补充**（按需追加）：
- 涉及手部动作（拿东西、写字、鼓掌）：追加"手部动作清晰自然、手指数量
  正确"。
- 多人物同框：追加"人物之间不重叠穿模、位置关系保持稳定"。
- 特写镜头：追加"面部五官保持清晰不模糊、不出现第二张脸"。

## 关于台词/对白（仅 LTX-2.5 自建通道，2026-08 实测确认）

大多数图生视频 SaaS 平台没有对口型/角色语音能力，台词只能作为参考信息
（见 `video_jobs_schema.md` 的 `dialogue` 字段），不要塞进提示词。**但
LTX-2.5 是例外**：它自带音频 VAE，能根据提示词描述自动生成同步音频，
实测确认（RTX PRO 6000 Blackwell WS，`ltx_pipelines.distilled`）：

- 提示词里如果只写动作/环境描述（不提声音），模型也会生成对应的环境音
  （比如描述"雨滴密集打落"就会带雨声），音量明显偏低（实测约 -55dB）。
- 把台词按官方示例的写法嵌入提示词——**声音质感/语气描述 + 语言声明 +
  "说道/说" + 引号台词**（例如"她用带着哭腔、颤抖又急切的**中文**声音
  小声说道：'台词内容'"），能让模型生成明显更响亮（实测 -15~-27dB）的
  语音，且**画面里角色的嘴型会随语音真实变化**（抽帧核对过，不是维持一个
  静止表情）。
- **必须显式声明目标语言，不要假设模型会自动按台词文字本身的语言生成**：
  只写"说道：'台词内容'"而不点明是"中文/普通话"，实测出现过角色说出
  英文或口齿不清、语种混杂的语音——即使引号里的台词本身就是中文文字。
  按本仓库项目的目标语言，在"声音质感描述"里明确加一个语言词（比如"用
  带着哭腔的中文声音说道"），这是目前唯一能提高命中目标语言概率的手段，
  但即便声明了也不保证 100% 命中，验收阶段仍要提醒用户实际听一遍确认
  语种和吐字是否正确（见 `video_review_checklist.md`）。
- **这一镜在 `ep0X.md` 里如果"台词/旁白"列有内容，且这一镜走 LTX-2.5
  通道，就必须按上面的格式把台词嵌入正向提示词，不能因为赶进度或者这句
  台词看起来不重要就漏掉**——漏嵌台词是"生成出来的视频没有台词、只有
  环境音"这类问题最常见的直接原因，不是模型能力不够，是提示词本身没有
  按格式要求把台词写进去。展开完 prompt 后回头对照 `ep0X.md` 的台词列
  过一遍，逐镜确认"这一镜该有台词的，prompt 里是不是真的写了"。
- **画外音/旁白/电话对方声音这类"声音来源不在画面可见角色身上"的台词**，
  一定要在提示词里明确写清楚"这是谁的声音，画面里的角色本人不说话/嘴唇
  不做说话动作"，并在负面提示词里加一条"角色出现说话时的嘴部张合动作"，
  否则模型可能误把画面角色的嘴型带偏，变成她在说别人的台词。
- **局限**：这条路径只在自建 LTX-2.5（`ltx_ssh_submit.py`）通道下适用，
  且 Claude 没有能力"听"生成出来的音频文件判断台词是否准确、音色/语气是否
  自然——只能通过 `ffmpeg -af volumedetect` 之类的工具判断"有没有声音、
  响不响"，内容和质感必须由用户实际听一遍确认，不要替用户下结论说"配音
  没问题"。
- 中文台词是否能生成准确口型/自然音色，官方文档的示例都是英文，目前只有
  零星实测（本仓库《千金归位》ep01 镜2/3/7/8/11），样本量很小，不代表
  普遍稳定，多镜头之间的音色一致性也未验证（每次生成是独立过程，没有
  跨镜头记忆）。

## 完整示例

**A 级示例**（对话反应镜，克制幅度）：

> 起始画面为参考图中人物近景，人物眼眶先泛红，睫毛轻微颤动，随后缓慢低下
> 头，嘴角向下撇，肩膀轻微抽动一下，最后定格于低头沉默的姿态短暂停顿。
> 镜头固定不动，不加运镜。光线保持与参考图一致的柔和自然光。
> 避免：人物面部变形、五官错位、多余肢体、手指数量错误、镜头抖动、
> 画面闪烁、人物中途换脸、水印字幕。

**S 级示例**（反转瞬间，大幅度）：

> 起始画面为参考图中人物跪地伸手的瞬间，人物猛然抬头，眼神从震惊转为
> 坚定，随后迅速起身站直，衣摆随动作剧烈摆动，最后定格于挺直站立、
> 目光直视前方的姿态并短暂停顿 0.5 秒。镜头缓慢向前推进，聚焦人物面部
> 表情变化。避免：人物面部变形、五官错位、多余或缺失肢体、手指数量错误、
> 肢体拉伸扭曲、镜头剧烈抖动、人物中途换脸、水印字幕、多余人物入镜。

## 关于时长

图生视频平台普遍单次生成上限在 5-10 秒（个别到 15 秒），提示词里不需要
写具体秒数（多数平台是单独的时长参数，不是写进 prompt 文本），但动作分解
的"过程关键点"数量要和目标时长匹配——2-3 秒的短片段只写 1 个过程关键点，
5 秒以上才适合写 2-3 个关键点，写太多动作点挤进一个短时长里，模型会把
动作压缩变形。长动作怎么拆成多段见 `stability_playbook.md`。

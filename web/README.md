# 剧本家协作网站

给剧本家看分镜表、人物/场景立绘、关键帧、视频，并且能留言、直接改文字、
导入剧本创建新项目、经审批生成图片的网站。设计背景和取舍见
`/home/codespace/.claude/plans/unified-churning-treehouse.md`（本次实现的
规划文档）。要把这套代码搬到公网云主机上长期跑给剧本家用，看 `DEPLOY.md`。

## 启动

零依赖，纯 Python 标准库，不需要 `pip install` 或 `npm install`：

```bash
python3 web/server/app.py --port 8000
```

浏览器打开 `http://localhost:8000` 就是你自己用；同一局域网内的剧本家把
`localhost` 换成这台机器的局域网 IP（比如 `http://192.168.1.23:8000`）
就能访问，不需要在自己设备上装任何东西。

**首次启动前必须先建至少一个登录账号**（否则所有页面/接口都会返回 401）：

```bash
python3 web/server/manage_users.py add <用户名>
```

会交互式提示输入密码（不回显、不进命令行历史）。每个剧本家可以有自己独立
的账号，参见 `manage_users.py --help` 增删账号/改密码。登录状态是签名
cookie（14 天过期），不是服务端 session 表，所以重启服务不会把已登录的
人踢下线；反过来，撤销某人访问权限目前只能靠改密码，不能"服务端主动踢
下线"，这是当前的已知限制。

如果这台服务部署在公网、前面有 HTTPS 反向代理（nginx+certbot 之类），
启动时加 `--secure-cookies`，让登录 cookie 带上 `Secure` 标记；纯局域网
内网跑（没有 HTTPS）不要加这个参数，否则浏览器会拒绝存这个 cookie 导致
登录不了。

**必须在这台机器上启动**（不能剧本家自己电脑上跑）：图片"重新生成"按钮
依赖本机已经 `codex login` 过的 Codex CLI，服务进程会直接在本机 fork
`codex exec` 子进程来出图。

## Codex 写提示词

右下角“使用帮助”可连续询问系统操作。固定通过 Codex 登录态调用 `gpt-5.6-luna`
（[官方模型文档](https://developers.openai.com/api/docs/models/gpt-5.6-luna)），不静默更换模型。
上下文包含操作指南、当前页面、有权访问的项目筹备进度和最近对话，不读取剧本正文或凭证。
助手只提供操作指引，不生成图片、不租卡、不审批。对话按账号保存在当前标签页，支持清空。
生产环境独立运行 `scriptwriter-help.service`（127.0.0.1:8001），nginx 精确转发
`/api/help/question`，避免重启主网站或占用主网站的文字生成槽位。单进程本地启动也提供该接口。

生成方式可选“完全重新生成”或“参考历史原文，按描述局部修改”。全新模式只将
本次描述传给 Codex，不传旧提示词，并清空默认历史参考图（可重新勾选）。局部修改
以当前提示词和选定历史版本为依据，定位描述涉及的部分，保留其他设定。

文字生成改为后台任务，`_web_state/prompt_tasks.json` 保存状态与结果。顶部“生成任务”
在所有页面可见，刷新后从服务器恢复。图片任务也统一在这里查看；编辑中的提示词、
描述、模式及参考图选择按账号和任务保存在当前浏览器，返回面板时恢复。
同一栏目的文字任务运行时重复提交返回原任务，图片运行时会阻止重复启动。
这些是网站功能，无需让用户安装或手动调用 skill；模型仅负责写文字，审批由服务端强制执行。

在人物、场景或关键帧的“重新生成…”面板里，先从同栏目缩略图中勾选参考图
（最多 6 张，支持放大；上次参考图默认勾选，可取消全部），再填写修改要求，
点击“Codex 按原文改写”。页面展示历史提示词来源和完整原文，Codex 同时收到
历史原文与当前编辑版本。历史版本下拉框可预览旧提示词，点“载入这个版本”才替换编辑框；支持撤销载入。
Codex 会以载入的版本作为原文依据。手动文本可保存版本，Codex 改写草稿自动保存。
结果可手动调整，点击“预览并审批图片生成”，检查完整提示词、参考图和张数，勾选确认后才会出图。

读取提示词时跳过空记录，依次回查历史生成记录、同 ID 原始 jobs 任务、
同栏目角色/场景设计档案。三处均无原文时要求补充完整提示词，不自动从零起草。
参考图显式传递给出图任务；取消全部会传空数组，确保不会自动恢复历史参考图。
写提示词只追加 `_web_state/prompt_history.json` 的文字版本，不生成图片。

## 从剧本创建项目

首页点“新建项目”，填写名称、目标集数、每集时长和画风，粘贴剧本或上传
TXT / Markdown / DOCX（最多 5 MB，正文 20–150000 字）。同名项目不能覆盖；
创建者自动有权访问自己的项目，其他普通账号仍需授权。

后台分步生成 `storyboard/` 中的风格简报、人物与场景设计、分集规划和逐集分镜，
以及 `assets/jobs_initial.json` 文字任务草案、选片占位文件和后续制作清单。
原始剧本保存在 `source/script.txt`，上传原文件也保留。生成进度及断点在
`_web_state/setup.json` / `foundation.json`，失败或服务重启后可继续，已完成的文件不会覆盖。
每次文字生成调用最多等待 600 秒，通过后台任务轮询进度。

筹备过程不调用任何图片、视频或租卡执行器。人物、场景与后续关键帧图片统一经过
`POST regenerate/preview` 保存待审批快照，`POST regenerate` 只接受该快照的
`approval_id` 和 `approved: true`；重复确认不会重复启动。同一审批 24 小时内有效。
审批记录在 `_web_state/approvals.json`。视频与租卡目前只列待办，必须先补齐
GPU 型号、单价、预计时长、预算上限和关机方案，另行由用户审批后执行。

后端调用 `codex exec`，使用运行网站的系统用户已经登录的 ChatGPT/Codex 账号
及其额度，无需另填 API key。网站账号的项目访问权限仍然生效；被授权的网站
用户共用服务器账号的额度，浏览器不会收到 Codex token。额度受账号方案限制。

服务器要求 Codex CLI 支持 `--ignore-user-config` 和 `--ephemeral`
（已验证 0.152.1）。默认使用 CLI 默认模型；可用环境变量 `CODEX_PROMPT_MODEL`
指定模型，`CODEX_BIN` 指定 CLI 路径。为避免个人配置干扰，提示词调用不加载
`config.toml`，认证仍由 CLI 管理。最多同时运行两个请求，单次超时 120 秒；
nginx 的 `proxy_read_timeout` 应设为 150 秒或以上，`client_max_body_size` 设为 `8m`，
以容纳 5 MB 文件的 JSON/base64 上传。项目筹备另需 CLI 支持 `--output-schema`。

官方说明：[Codex 自动化调用](https://learn.chatgpt.com/docs/non-interactive-mode)、
[认证与账号额度](https://learn.chatgpt.com/docs/auth)。

## 目录说明

```
web/
  server/    Python 后端（stdlib http.server，无第三方依赖）
  frontend/  纯静态前端（无构建步骤，浏览器直接加载）
  content/   guide.md：渲染给剧本家看的指南正文，改这个文件就能改指南内容
```

产出会落在各项目自己的 `output/<剧名>/_web_state/review.json` 里：剧本家
的评论、图片入选标记、分镜表文字修改的审计记录、重新生成请求/状态。这个
文件正常提交进 git（子目录下的 `logs/` 是子进程日志/临时文件，已加进
`.gitignore`）。下次处理这个项目时，直接读这份 `review.json` 或者用
`GET /api/inbox` 就能看到剧本家提了什么意见。

## "重新生成"按钮的边界

- **人物立绘 / 场景图 / 关键帧图**：使用服务器的 Codex 图片额度，先预览并审批，
  确认后才实际生成。
- **视频**：不支持一键生成。多数平台要求人工网页提交，自建 LTX-2.5 那条
  路虽然能脚本化但会真花钱租显卡，所以视频页的"重新生成"只登记一条待办，
  不执行任何操作。

## 已知限制（MVP 阶段）

- 浏览器换页/刷新不影响后台任务。服务器进程重启时，未完成文字任务会标为中断，
  图片的原进程句柄可能无法恢复；任务记录会保留，先检查结果再重试。不会自动重新出图。
- 分镜表/视频清单的文字编辑只处理"文件里第一张表格"，且要求单元格里没有
  真的想保留原样的换行——保存时会把换行压成空格。
- 登录是每人独立账号+密码（`manage_users.py` 管理），会话用签名 cookie，
  没有"服务端强制踢人下线"的能力，撤销权限只能改密码；也没有找回密码/
  忘记密码流程，忘了密码只能让管理员用 `manage_users.py passwd` 重设。
- 登录失败有基础的按用户名限流（5 分钟内同一用户名连续错 8 次会先拒绝，
  不再校验密码），但没有做更严格的防暴力破解（比如按 IP 限流、验证码），
  只适合"熟人小团队"规模的公网暴露，不是给大规模公开访问设计的。

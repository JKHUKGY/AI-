# 出了问题该回哪一层修：故障 → 层 → 具体动作

## 为什么需要这份表

现在的重试循环有个结构性缺陷：**它只会拿同一张首帧反复重生成视频**。

首帧是用 `--image PATH 0 1.0` **焊死**的，模型必须从那一帧长出来。所以如果
**那张图本身就不适合这一镜**——人物朝向不对、这个机位根本看不到该看的东西、
上一镜在场的人这张图里没有——那么无论重试多少轮、把提示词改得多细，
都改不出来。**问题在上游，重试在下游，永远修不好。**

2026-09-04 实测确认过一个最典型的例子：ledger **A9「人物自己转向镜头」**。
首帧是 3/4 侧面，成片里人在第 1 秒就转成正面。我们试过在 `preserve_en` 里
加显式的朝向锁定句，**1.0 / 0.95 / 0.85 三档 strength 全部照样失败**。
这条在视频层已经没有已知修法了——唯一的出路是回到关键帧层换个思路。

所以循环需要**第三种结论**：不是"过"、也不是"再生成一次视频"，而是
**"升级到上游改，然后重出首帧"**。

---

## 三层结构

| 层 | 产物 | 改什么 | 改完要重跑 |
|---|---|---|---|
| **L1 视频层** | `shot_cards.json` → `video_jobs.json` / `h3_jobs.json` | 逐拍动作、时长、节拍分配、seed、拆段、局部重绘 | 装配 + 重新提交生成 |
| **L2 关键帧层** | `keyframe_cards.json` → 关键帧 PNG | 走位、朝向、景别裁切、机位（底板）、参考图、在场人物 | 重出图 + 回填 `first_frame` + 重新生成视频 |
| **L3 分镜层** | `ep0X.md` | 这一镜用哪个机位、要不要拆成两镜、越轴、要不要删掉这一镜 | 重做关键帧卡 → L2 → L1 |

**判断顺序永远是从下往上**：先问"这个能在 L1 修吗"，不能才上 L2，
L2 也不能才上 L3。**别一上来就重做分镜**，那是最贵的。

---

## 路由表：看到什么现象，回哪一层

### 判定归 L1（视频层）——重试视频就有希望

| 现象 | 为什么是 L1 | 具体改什么 |
|---|---|---|
| 台词没说完 / 被吞字 | ledger A2：字数超时长，模型自己压缩 | 加 `duration_sec`；或把这一拍拆成两个单元 |
| 动作幅度过大、糊成一团 | 逐拍动作写得太满 | 减少 `beats` 数量，一拍只留一个动作 |
| 只有镜头在动、人物不动 | ledger A3：节拍描述的是首帧**之前**的动作 | 对照 `first_frame_state_zh` 改节拍，从图里已有的状态**继续** |
| 推拉冲过头、脸在最近处漂 | ledger A8 | `camera_en.framing_path` 写死落幅：`only as far as … then holds` |
| 只有一小段时间窗口坏 | 其余画面正常 | `--retake <start> <end>` 局部重绘，别整段重来 |
| 同一提示词多次结果都怪 | 可能是这个 seed 不好 | 换 `seed` 再试一轮 |

### 判定归 L2（关键帧层）——**必须重出首帧，重试视频是浪费钱**

| 现象 | 为什么重试视频没用 | 关键帧卡改哪个字段 |
|---|---|---|
| **人物在第 1 秒转成正面朝镜头** | ledger A9，已实测：视频层提示词拦不住 | 要么接受正面、把卡的 `camera_relation` 直接改成 `front` 让首帧就是正面（至少前后一致）；要么改 `gaze_at` 让他**明确在看画内的某个人/某件道具**——用画内动机压过"转向镜头"的先验（未验证，值得试） |
| **上一镜在场的人，这一镜画面里没有** | 首帧里就没有这个人，模型不会凭空加 | **2026-09-04 起这一条应该在关键帧阶段就被硬拦掉**：`scene_beats[].present` 列出在场的人，每一镜的 `people` / `background_people` / `present_off_frame` 三个名单必须正好覆盖它。走到 L2 才发现说明那一集还没迁移到带 `scene_beats` 的新格式——先迁移，再把这个人写进 `background_people[]`（带参考图或 `appearance_zh`） |
| **画面里的沙发/餐桌是空的**（上一镜还坐着人） | 同上，而且更隐蔽——单看这一张图没有任何毛病 | 同上。装配器的家具规则专门抓这个：取景说明里点到了某件家具、而同场次有人坐在那件家具上、这一镜又没交代他 → ERROR |
| **这个机位根本看不到该看的东西** | 底板决定了能看到什么 | 换 `plate_id`（A主机位/B反打/C侧机位/D细节），并按新机位重写 `pos_x`/越轴 |
| **标着某个机位，出来却是一个全新的机位**（房间还是那个房间，但相机位置变了） | 近景/特写挂在**宽景定场底板**上：底板里没有那个距离的像素，模型只能重新合成一个相机，一合成"保持场景一致"就整体失效 | 把 `plate_id` 换成该机位的**紧底板**（`..._紧`）。没有就先派生一张，见 `short-drama-storyboard/references/scene_prompt_template.md`「焦段」一节。**场次主帧顶替不了紧底板**——主帧也是宽图，同一个像素问题 |
| **景别不对**（要特写出成了全身） | 首帧的裁切就是那样，视频改不了画框 | `framing.crop_zh` 改成"把人物从X处切断、看不到Y"的句式；`subject_frac` 按景别调 |
| 人物朝向跟对话逻辑矛盾（该看左边却看右边） | 首帧焊死了朝向 | `body_dir` / `camera_relation` / `gaze_at` 三个字段一起改，并跑越轴校验 |
| 人物长相/服装跟前一镜对不上 | 首帧就画错了 | `people[].ref_images` 换成正确的角色三视图版本；`ref_note_zh` 写清用哪一版 |
| 手部/道具特写里东西画错了 | 同上 | 道具外观写进 `scene_beats[].state_zh`——**它会被这一场每一镜的提示词自动重复一遍**，比逐张卡手抄 `props_zh` 可靠。模型不跨镜记忆 |

### 判定归 L3（分镜层）——关键帧也救不了

| 现象 | 为什么 | 改什么 |
|---|---|---|
| 这一镜的信息量撑不住它的时长 | 本来就没内容可演 | `ep0X.md` 里把这一镜合并进相邻镜，或缩短 |
| 连续三镜同一底板，看着像 PPT | 机位设计问题 | 给其中一镜换机位，同时核对越轴 |
| 这一镜要求的动作物理上做不到（比如一镜里换三个场景） | 分镜写得不可拍 | 拆成多镜 |
| 台词太长，拆段也塞不下 | 单元时长上限（LTX 无硬限但长了必崩；H3 硬性 5–15 秒） | 回 `ep0X.md` 把台词拆到两镜 |

## Reviewer 怎么给出可执行的升级结论

判定为 L2 时，光说"首帧不对"没用。**必须给出三样东西**，下游才能直接执行：

```json
{
  "verdict": "escalate_l2",
  "why": "镜24 首帧里顾瑶是端坐的，分镜要求半躺+小腿架扶手；视频层改不了姿势",
  "keyframe_card_patch": {
    "people[顾瑶].posture_zh": "整个人半躺着陷在转角沙发靠南那一段里——后背斜靠在沙发靠背上、上身几乎放平，一条小腿架在沙发扶手上"
  },
  "recheck": "重出图后逐张看：小腿是不是真的架在扶手上、两人是不是都没抬头"
}
```

- `keyframe_card_patch` 用**字段路径 → 新值**的形式，不写散文意见
- `recheck` 是重出图之后要**逐张看什么**，避免重出一张同样有问题的
- 打到 `scene_beats` 那一层的补丁用 `scene_beat_patch`，字段路径写成
  `scene_beats[ep01_b3].state_zh[+]` 这样。**连戏类的问题几乎总该打在
  节拍上，不是打在单张卡上**——打在卡上只修好这一镜，同一场的其它镜下次
  还会犯

## 升级之后的完整回路

L2 升级不是改一个文件就完了，是一条链。`scripts/rekey_shot.py` 把这条链
包起来了（见脚本头部说明），手动做的话顺序是：

1. 改 `keyframes/ep0X/keyframe_cards.json` 里这一镜的卡（或它所属的
   `scene_beats` 条目——改了节拍的 `state_zh`/`present`，**这一场所有镜的
   提示词都会跟着变**，要一起重出）
2. `build_keyframe_prompt.py --only <镜id>` 重新装配提示词（**不手改提示词**）
3. `generate_images.py` 重出图
4. **逐张打开看**，确认改的那一点真的改过来了
5. 把选中的新图路径填回 `videos/ep0X/shot_cards.json` 的 `first_frame`
6. **重新写 `first_frame_state_zh`**——这一步最容易漏。新图的姿态跟旧图不一样，
   节拍必须从**新图**已有的状态继续，否则立刻掉进 ledger A3
7. `build_prompt.py` / `build_h3_prompt.py --only <镜id>` 重新装配
8. 重新提交生成

**第 6 步漏了会怎样**：新首帧 + 旧节拍 = 节拍描述的动作在新图里已经发生完了
= 人物不动只有镜头动。这正是我们在第一批 16 镜里踩到 7 次、第二批 19 镜里
踩到 10 次的那个坑。

---

## 预算：L2 升级也要有上限

L2 比 L1 贵（要重新出图 + 重新跑视频），所以同样要封顶：

- **单镜最多升级 1 次 L2**。升级完再失败就放行，标记 `capped_l2`，
  留给人工决定要不要上 L3。
- L1 的三轮上限**不因为升级而重置**：一镜总预算是"最多 3 轮 L1 + 最多 1 次 L2"。
- L3 **永远不自动做**——分镜是创作决定，必须人来拍板。Reviewer 判到 L3
  就停下来把结论交给用户，不要自己动 `ep0X.md`。

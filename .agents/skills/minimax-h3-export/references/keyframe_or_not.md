# H3 到底还要不要关键帧这一步

## 先说结论

**三种做法都成立，默认用「关键帧当分镜参考」这一种**（下面的 B 方案）。
但三种都**没有实测过**，第一次跑 H3 时应该拿同一镜跑三遍做对照，
把结果写回这份文档。

---

## 为什么会有这个问题

关键帧这一步是**为 LTX 的机制而存在的**，不是天然必需的。

LTX-2.5 的图生视频是 `--image PATH 0 1.0`：**把一张图焊死成第 0 帧**，
模型只能从那一帧往后长。它没有"给我角色照片和场景照片，你自己组合"的能力。
所以我们必须先用出图模型把「这一镜的人按走位站进这个场景」合成出来——
这就是 `short-drama-keyframe-gen` 存在的全部理由。

**H3 的 ref2va 不是这个机制。** 它天生吃一组参考：

- `<Subject N>` 官方定义的适用范围包括**人、动物、物体、场景、背景、环境、
  服装、道具、界面、特效、风格、动作、表情、姿势**
- `<Picture N>` 可以是"某镜的首帧/关键帧/尾帧"，**也可以是分镜参考**——
  官方原话：`<Picture 3> is a storyboard reference for [Shot 1] and [Shot 2],
  defining their viewpoint, subject placement, and shot order.`
- 上限：图 ≤9、视频 ≤3、音频 ≤3，跨类型总数 ≤12

也就是说 **H3 自己就能做关键帧那一步的活**：给它角色三视图 + 场景底板 +
一段写清走位的 `detailed_description`，它可以直接生成。

**而且素材是现成的**——`keyframe_cards.json` 里本来就有每一镜的
`plate_image`（按机位组织的场景底板）和每个人的 `ref_images`（角色三视图）。
关键帧只是这两样的合成产物。不走关键帧**不需要补任何新素材**。

---

## 三种做法

### A. 关键帧当首帧（`--keyframe-role first_frame`）

```text
<Picture 1> is the first frame of [Shot 1], establishing the composition,
subject placement, lighting and scene of the shot.
...
<Picture 1> ([Shot 1] first frame): fully_preserved - ...
```

最接近 LTX 的做法，构图确定性最高。

### B. 关键帧当分镜参考（`--keyframe-role storyboard`）← **默认**

```text
<Picture 1> is a storyboard reference for [Shot 1], defining its viewpoint,
subject placement, framing and scene.
...
<Picture 1> ([Shot 1] storyboard reference): partially_preserved - the
viewpoint, subject placement and framing are followed; the shot is free to
move away from it over time.
```

同一张图，但**不声明它是第 0 帧**，`retention` 从 `fully_preserved` 降成
`partially_preserved`。保留了人工审查过的构图，同时给模型运动空间。

### C. 不用关键帧（`--keyframe-role none`）

```text
<Subject 1> is the location ... from the supplied scene plate (SC06_机场出口_B反打)
<Subject 2> is 江砚, whose appearance ... from the character reference sheet
<Subject 3> is 苏慧, ...
```

场景底板和角色三视图各自当 `<Subject N>`，走位全靠
`detailed_description` 里的文字。**整个 `short-drama-keyframe-gen` 阶段跳过。**

---

## 区别在哪：四个维度

### 1. 成本

| | 关键帧出图 | 每镜素材数 |
|---|---|---|
| **A / B** | **每镜 1 张**（还要验收，不合格重出） | 1 张关键帧（+ 可选角色图） |
| **C** | **0** | 1 张底板 + N 张角色三视图 |

这是 C 最大的优势。ep01 光关键帧就出了 35 张、其中 4 张要重出，
外加逐张打开验收——**这是整条流水线里人工投入最重的一段**。

### 2. 人工审查闸门 ← **这是 A/B 最大的价值，别轻易丢**

`short-drama-keyframe-gen` 不只是"出张图"，它是一道**能在出视频之前就
发现问题的关卡**，带一整套强制校验：

- 一镜最多一人正脸
- 多人镜必须有人过肩/背对
- 多人镜必须分纵深层
- 景别必须写成裁切线
- 正反打必须越轴
- 参考图路径必须存在

而且**图比视频便宜得多**。走位错了在关键帧阶段花几毛钱重出一张，
比在视频阶段烧显卡重跑一条划算一个数量级。

**走 C 就等于把这道闸门拆了**——走位、朝向、越轴、景别只剩文字描述，
错没错要等成片出来才知道。

### 3. 跨镜空间连续性

我们的场景底板是**按机位组织**的（A主机位 / B反打 / C侧机位 / D细节），
每个地点一组，外加一段空间关系描述。这是为了保证同一场戏的正反打不越轴。

- **A / B**：关键帧是从指定底板裁出来的，机位关系是**焊在图里**的。
- **C**：给的是"这个场景的某张底板"，**每镜的机位由模型自己决定**。
  越轴保不保得住？**不知道，没测过。** 这是 C 最大的未知风险。

### 4. 跟 A9 的关系（可能是 B 方案的真正收益）

ledger **A9「人物自己转向镜头」** 是 LTX 上实测确认、改提示词拦不住的硬故障：
首帧是 3/4 侧面，成片第 1 秒就转成正面。三档 `first_frame_strength`
（1.0/0.95/0.85）全部失败。

**根因推断是"焊死的首帧"和"模型想画正脸"这两个约束在打架**——模型在
"照首帧"和"照先验"之间摆烂。

- **A** 最接近 LTX 的焊死语义，**最可能复现 A9**
- **B** 图只是参考、不是焊死的帧，两个约束不再硬冲突，**可能绕开**
- **C** 完全没有构图约束，人物朝向只剩文字管——**可能更容易转正面**

所以在 A9 这条上，**B 很可能是最优点**：既有构图引导，又不制造矛盾。

---

## 默认选 B 的理由

| | A 首帧 | **B 分镜参考** | C 不用关键帧 |
|---|---|---|---|
| 出图成本 | 高 | 高 | **零** |
| 人工审查闸门 | ✅ | ✅ | ❌ |
| 构图确定性 | 最高 | 高 | 低 |
| 越轴/机位连续性 | ✅ | ✅ | ❓ 未知 |
| 绕开 A9 的可能 | 低 | **最高** | 中（但朝向全靠文字） |
| 运动自由度 | 最低 | 中 | 最高 |

**B 在"保住闸门"和"不制造矛盾"之间**。而且我们 ep01 的 35 张关键帧已经
出好了，B 能直接复用，不浪费。

**什么时候该考虑 C**：
- 新剧、还没做关键帧，想先快速看整集的样子
- 某一镜反复在关键帧阶段出不对（比如走位太复杂），不如直接让 H3 自己组
- 纯空镜、或者只有一个人的简单镜头，走位没什么可审的

**什么时候必须 A**：
- 这一镜的构图是精心设计的、一点都不能动（比如 ep01 镜23 的二楼俯拍）
- 要跟前一镜做严格的动作接续

## 怎么验（第一次跑 H3 时做掉）

拿一个**双人对话镜**（走位和越轴都有内容的，比如 ep01 镜20）跑三遍，
其余参数完全一致，只换 `--keyframe-role`。看四件事：

1. **人物有没有转向镜头**（A9）——这是最关键的一条
2. **构图跟设计的差多少**——景别、左右位置、纵深层
3. **人物长相跟三视图对不对得上**
4. **C 的机位有没有跑偏**——生成的视角是不是还在那个底板的机位上

结果写回这份文档，把"默认 B"这个结论要么坐实要么推翻。
